# JMVCC Bridge — мост «агент ↔ клиент Minecraft»

Клиентский мод Fabric (Minecraft 26.2, Fabric Loader 0.20.x, Fabric API 0.161.0+26.2, Java 25)
и CLI `jmvcc client ...`. Цель: агент сам заливает модуль, запускает мир и читает логи и ошибки
сервера, без участия игрока. Игрок в любой момент режет доступ командой `/j remote off`.

Код мода: `client-mod/`. CLI: `src/core/client/Bridge.ts` + команды в `src/index.ts`.

## Обнаружение

Мод при старте пишет `%USERPROFILE%/.jmvcc/bridge.json` (на других ОС `~/.jmvcc/bridge.json`):

```json
{ "port": 47321, "token": "<32 hex>", "pid": 1234, "gameDir": "D:\\minecraft\\game", "version": "0.1.0", "startedAt": 1793642510659 }
```

Токен и порт хранятся в `<gameDir>/config/jmvcc-bridge.json`:
`{ "remote": true, "port": 47321, "token": "..." }`. Токен генерируется при первом запуске.
Если порт занят, мод пробует следующие 10 портов и пишет в bridge.json тот, что занял.

## HTTP API

- Адрес только `127.0.0.1:<port>`.
- Каждый запрос с заголовком `Authorization: Bearer <token>`, иначе 401.
- Тела запросов и ответов — JSON в UTF-8.
- Ошибка — HTTP 4xx/5xx и `{ "error": "<code>", "message": "<по-русски, для агента>" }`.

Мутирующие запросы (`/command`, `/deploy`, `/stop`, `/click`, `/use`, `/close`, `/key`, `/button`) при выключенном управлении
отдают **403**:
```json
{ "error": "remote_disabled", "message": "Игрок отключил удалённое управление клиентом (/j remote off). Напиши ему об этом в чате и попроси включить: /j remote on" }
```
Если игрок не на сервере — **409** `{ "error": "not_connected" }`. Если идёт другая автоматическая
операция — **409** `{ "error": "busy" }`.

### GET /status
```json
{ "remote": true, "connected": true, "server": "mc.justmc.ru", "player": "Morphill",
  "dimension": "minecraft:overworld", "screen": null | "GenericContainerScreen", "busy": false,
  "session": "2026-11-02_18-56-52", "logVersion": 1,
  "drain": { "active": false } | { "active": true, "by": "player" | "agent", "leftMs": 41000 } }
```
`drain` — идёт ли мягкая остановка мира (см. ниже); `leftMs` — сколько ещё код доигрывает (0 — код ещё не ответил).
Нет поля — мод старее 2026-11-04 (не знает `graceful` и `POST /stop`).

### GET /sessions
`{ "sessions": [ { "id": "2026-11-02_18-56-52", "start": <ms>, "end": <ms>|null, "reason": "world_started", "events": 42, "errors": 1 } ] }`,
новые в конце.

### GET /logs?session=current|<id>&types=error,warning,critical,log,system,chat&since=<seq>&limit=<n>
`types` по умолчанию: всё, кроме `chat` и `broadcast`. `since` — вернуть события с `seq > since`.
```json
{ "session": "…", "events": [ <event>, … ], "last": <seq> }
```

**Событие** (одна строка jsonl в файле сессии):
```json
{ "seq": 17, "time": 1793642510659, "type": "error",
  "text": "❌ Ошибка\nДействие Установить значение словаря остановило строку кода из-за ошибки:\n\nОжидал аргумент …",
  "action": "Установить значение словаря", "reason": "Ожидал аргумент \"Словарь для изменения\" с типом Словарь, но получил Число",
  "block": [20, 5, 6], "json": { …исходный компонент… } }
```
Типы:
- `error` — сообщение сервера с `❌` или «остановило строку кода»; `block` — из click_event `/editor tp x y z`.
- `warning` — как error, но с `⚠` / «Предупреждение»; `critical` — «Критическ…» / `‼`. Если формат непонятен,
  но есть click_event `/editor tp`, тип `code_notice` (сохраняем всё, классифицируем потом).
- `log` — сообщение, которое начинается с маркера U+2063 (невидимый разделитель). Маркер ищется после
  необязательной метки времени `[hh:mm:ss] `, которую добавляют чат-моды. В `text` маркер и метка срезаны.
  В JustCode: `log("text $x")` → `player::message<all_players>("\u2063text …")`.
- `system` — `🔔 »` / `✔ »` сообщения сервера (загрузка модуля, запуск мира) и всё не-чатовое.
- `broadcast` — объявления на весь сервер: наказания от модерации (`🗡 » Support X заблокировал чат …`) и
  реклама (`JustMC ⁎ Creative …`, `justmc.io`). К коду игрока не относятся.
- `chat` — сообщения игроков (`[!] …` — глобальный, `⏵ …` и прочие).
- `session` — служебные: `{"type":"session","event":"start"|"join"|"leave","reason":…, "offlineMs":…}`.

**Сессии** (файлы `~/.jmvcc/logs/<id>.jsonl`, индекс `~/.jmvcc/logs/index.json`):
- новая сессия начинается на сообщении «Мир запущен в режиме игры» (`reason: world_started`) и при входе
  на сервер (`reason: join`);
- при выходе с сервера в текущую сессию пишется `session/leave`; при следующем входе — `session/join` с
  `offlineMs` (сколько был оффлайн). Переходы между мирами без выхода (`/build`, `/dev`, `/play`) событий
  не пишут; первый вход после запуска игры — только `session/start`;
- id сессии — локальное время старта `YYYY-MM-DD_HH-mm-ss`.

### POST /command `{ "text": "/build" }`
- `/...` → команда серверу, иначе сообщение в чат.
- **Запрещено**: сообщения, начинающиеся с `!` (глобальный чат) → 403
  `{ "error": "global_chat_blocked", "message": "Сообщения с ! уходят в глобальный чат — мост их не отправляет" }`.
- Ответ: `{ "ok": true, "sent": "/build" }`.

### POST /deploy `{ "url": "https://m.justmc.ru/api/<id>", "play": true }`
Цепочка (между шагами пауза ~1 с, у каждого ожидания таймаут):
1. `/build` (останавливает мир), ждать 1.5 с;
2. `/dev` (мир кодинга), ждать смену измерения/мира или 5 с;
3. `/module loadUrl force <url>` → ждать «успешно импортирован» (успех) или сообщение об ошибке (таймаут 30 с). Если сервер открыл книжку подтверждения («Установка … сотрёт весь код мира — ПРИНЯТЬ / ОТКАЗ», появляется не всегда) — мод выполняет команду кнопки «ПРИНЯТЬ» и закрывает книжку; в шаге `book`: команда;
4. если `play`: `/play` → ждать «Мир запущен в режиме игры» (таймаут 30 с).

Ответ:
```json
{ "ok": true, "steps": [ { "step": "build", "ok": true }, …, { "step": "play", "ok": true, "ms": 4100 } ],
  "session": "2026-11-02_19-01-50" }
```
При неудаче — `ok: false`, на шаге `error` (`timeout`, `module_error`, текст сообщения сервера).

**Мягкая остановка**: `{ "url": "…", "graceful": true, "timeout": 90 }` — перед `/build` код мира доигрывает сессии
(протокол — ниже), `timeout` — сколько секунд ему дать (1..600, по умолчанию 90; без `graceful` не действует; 0 — 400: код мира прочёл бы его
как «не дано» → 90, не ждать — обычный deploy). Первым
в `steps` идёт шаг `drain`:
```json
{ "step": "drain", "ok": true, "result": "ready", "timeout": 90, "message": "Код доиграл сессии …", "ms": 12300 }
```
`result`: `ready` — код ответил `jmvcc:ready-to-stop`; `timeout` — ответил `jmvcc:draining`, но не `ready-to-stop` за
`timeout` + 10 с, и на `#jmvcc status` — `draining=1` или ничего (строка обработчика умерла) — дальше `/build` жёстко
(`draining=0` — остановку отменил кто-то другой: `cancelled`, `/build` не шлётся); `no-receiver` — нет `jmvcc:draining` за 3 с (в
коде нет мягкой остановки) — дальше как раньше; `forced` — игрок набрал `/j build force`. Эти — `ok: true`, цепочка
идёт дальше. `cancelled` (`/j build cancel` или код ответил `jmvcc:cancelled`) и `aborted` (`/j remote off` —
`error: remote_disabled`, мод тогда сам шлёт `#jmvcc cancel`; игрок вышел — `not_connected`; игрок не в мире —
`not_in_world`; сменил мир, перезашёл или мир перезапущен (`/build` руками, `/play`, переход в другой мир) —
`world_changed`: `/build` остановил бы уже другой мир или новый запуск) — `ok: false`, в `steps` только `drain`,
`/build` не отправлен. `timeout` в шаге — сколько секунд код доигрывает (из `jmvcc:draining N`, но не больше
запрошенного: мод не ждёт дольше `timeout` из запроса).
Пока код доигрывает, ввод игрока НЕ блокируется (это минуты): плашка «⏳ JMVCC: мир доигрывает — ещё N с ·
/j build cancel» и title «🤖 Агент перезапускает мир»; сама цепочка (`/build` …) — как обычная операция (title, пауза
1 с). Сессия управления (`/control`) не кончается посреди ожидания. 409 `busy` — игрок сам останавливает мир
(`/j build`) или идёт другая операция. Ожидание до `timeout` + 16 с — HTTP-клиенту ставить таймаут с запасом.
`#jmvcc build N` уходит обычным сообщением в чат того мира, где игрок: в мире без приёмника (старый модуль) его
увидят все и получит `player_chat` кода. Мод проверяет только, что игрок в мире, — не что мир свой.

### POST /customclick `{ "id": "jmvcc:rpc", "snbt": "{cmd:\"status\"}" }` | `{ "id": "…", "text": "…" }`
Пакет custom click (1.21.6+) — сервер видит `event<player_custom_click>` без чата и окон. `snbt` — SNBT-compound:
в коде `value::event_custom_click_dialog_view_data` — словарь (`{a:1,b:"x"}` → `{b=x, a=1}`); `text` (строка, не
compound) приходит пустым словарём — для данных бери `snbt` (server-check-25). CLI: `jmvcc client customclick <id>
[--snbt <s> | --text <s>]`. 400 `bad_request` (id не namespace:path, кривой SNBT), 409 `not_connected`.

### POST /stop `{ "timeout": 90 }`
Только остановить мир: мягкая остановка → `/build`, без `/dev` и заливки. Ответ как у `/deploy`: `steps` — `drain`,
`build`. Нет мягкой остановки в коде (`no-receiver`) — `/build` сразу. `timeout` 1..600. 403 `remote_disabled`,
409 `not_connected`, `busy`.

### Протокол мягкой остановки (мод ↔ код мира)
- Мод → код: пакет custom click `jmvcc:cmd` с данными `{cmd:"build <таймаут_с>"}`, `{cmd:"cancel"}`, `{cmd:"status"}`
  (мод с 2026-11-04 14:10: любой текст `#jmvcc …` в `POST /command` / `client send` уходит так же). Мир без приёмника
  пакет молча игнорирует. Код принимает и сообщение в чат `#jmvcc build 30` (набрать руками), отменяет событие —
  в чате мира его не видно. Принимает от игрока с `DEVELOPER` или `OWNER`.
- Код → мод: строки `log()` (тип `log` в журнале): `jmvcc:draining <таймаут>` (сразу на build),
  `jmvcc:ready-to-stop` (всё доиграно или таймаут кода, `on_stop` отработал), `jmvcc:cancelled`,
  `jmvcc:status draining=<0|1> busy=<число>`. Мод ждёт `draining` 3 с, `ready-to-stop` — таймаут из `draining` + 10 с,
  потом спрашивает `#jmvcc status`: `draining=0` — отменено, `/build` не слать.
- Таймаут 1..600: `#jmvcc build 0` мод не шлёт (код читает 0 как «число не дано» → 90).
- Ждёт мод только в том запуске мира, где начал: смена мира, повторный вход, «Мир запущен в режиме игры» — `aborted`.
- Код сам `/build` не делает (такого действия нет): `/build` шлёт мод после `ready-to-stop`.
- Служебные строки `log()` с `jmvcc:` мод в чате не показывает (в журнале они есть) — ход показывает сам.

### GET /screen
```json
{ "screen": "GenericContainerScreen", "title": "Магазин", "slots": [ { "index": 0, "id": "minecraft:diamond", "count": 1, "name": "первый" }, … ],
  "playerSlotsFrom": 27 }
```
`screen: null`, если ничего не открыто. В `slots` только непустые.

### GET /inventory
Предметы инвентаря игрока и открытого окна-контейнера — со строкой сервера `raw` для `item_raw("…")` в JustCode
(головы `/hdb`, предметы со своими текстурами, именами, lore — то, что не собрать `item(...)`). Чтение: без title,
работает и при `remote off`.
```json
{ "inventory": [ { "slot": 9, "section": "main", "id": "minecraft:player_head", "count": 1,
                   "name": "Billiard Cue Ball", "customName": true, "lore": ["…"], "raw": "H4sIAAAAAAAA/…" } ],
  "selected": 0,
  "carried": null | { "id": "…", "count": 1, "name": "…", "customName": false, "raw": "H4sI…" },
  "creative": false,
  "container": null | { "screen": "ContainerScreen", "title": "HeadDatabase",
                        "slots": [ { "index": 3, "id": "…", "count": 1, "name": "…", "customName": true, "raw": "H4sI…" } ] } }
```
- `slot` — номер в инвентаре: 0–8 хотбар (`section: hotbar`), 9–35 рюкзак (`main`), 36–39 броня ноги…голова
  (`armor`), 40 вторая рука (`offhand`). Только непустые. `selected` — выбранный слот хотбара.
- `container.slots` — только слоты самого окна (без инвентаря игрока), `index` — как в `GET /screen` и `POST /click`.
  При открытом креативном инвентаре `container: null` и `creative: true`: его вкладки — каталог всех предметов, а не
  вещи игрока. `carried` — предмет на курсоре (взят из слота в открытом окне), иначе `null`.
- `name` — имя, которое видно в игре; `customName: true` — своё имя: `minecraft:custom_name` (головы `/hdb`) или
  `minecraft:item_name`, изменённый у предмета (предметы плагинов, меню сервера) — как `summarizeItem` в
  `jmvcc decompile`; `false` — стандартное имя предмета на языке игры.
- `raw` — предмет как в выгрузке модуля сервера: base64 (с `=`) от gzip бинарного NBT, корень — безымянный компаунд
  `{DataVersion: 4903 (26.2), id: "minecraft:player_head", count: 1, components: {"minecraft:profile": {…},
  "minecraft:custom_name": {…}, …}}` (components нет у простого предмета). Мод кодирует `ItemStack.CODEC` с реестрами
  мира + `DataVersion` клиента + gzip JDK (как `NbtIo.writeCompressed`). NBT тот же, что у сервера; порядок ключей
  внутри компаундов у сервера свой, поэтому строка может отличаться от выгрузки байтами, но не содержимым (тот же
  предмет из выгрузки и из `/inventory` — две разные строки, jmvcc их не склеивает).
  `DataVersion` — версия клиента (`SharedConstants`), не сервера: клиент не должен быть новее сервера, иначе сервер
  получит предмет «из будущего» и может его не прочитать (сейчас оба 26.2 → 4903).
  Количество входит в `raw` (стопка из 3 голов → предмет ×3).
- `rawError` вместо `raw` — предмет не закодировался (сообщение кодека).
- 409 `not_connected` — игрок не в мире. Нет метода (404 `not_found`) — мод старее 2026-11-03.

### POST /click `{ "slot": 0, "button": "left" | "right", "shift": false }`
Клик по слоту открытого контейнера. Ответ `{ "ok": true }`. 409 `no_screen`, если окно не открыто.

### POST /use `{ "hand": "main" | "off" }`
Правый клик предметом в руке (открыть меню и т.п.). `{ "ok": true }`.

### POST /close
Закрыть открытое окно.

### POST /button `{ "text": "Возродиться" }`
Нажать кнопку открытого экрана по тексту (регистр и знаки не важны; сначала точное совпадение, потом вхождение).
Для экранов без слотов: смерть, подтверждения, диалоги. Кнопки экрана — в `GET /screen` (`buttons: [{text, active}]`).
Ответ `{ "ok": true, "pressed": "Возродиться" }`. 409 `no_button` (в сообщении список кнопок), `button_inactive`
(экран смерти включает кнопки через секунду), `no_screen`; 403 `button_blocked` — кнопки выхода с сервера
(«Главное меню», «Отключиться», «Выйти»…) мост не нажимает. Меню паузы мост закрывает в начале любой операции.

### POST /key `{ "key": "forward" | ["forward", "sprint"], "ms": 100 }`
Нажать и держать клавиши `ms` миллисекунд (50..10000, по умолчанию 100). Имена: `forward back left right
jump sneak sprint swap_offhand drop attack use inventory hotbar1`..`hotbar9` — клавиши из настроек игрока.
Нажатие — это и клик (срабатывают `swap_offhand`, `drop`, `hotbarN`), и удержание (ходьба, присед).
Ответ `{ "ok": true, "pressed": [...], "ms": 2000 }` — после того, как клавиши отпущены.
400 `bad_key` — нет такой клавиши (в сообщении список); 409 `screen_open` — открыто окно, клавиши не
дойдут до игры (`POST /close`); меню паузы не считается — мост его закроет сам. Пока агент держит клавиши, клавиатура игрока игнорируется.

### POST /control
Сессия управления: `{ "action": "begin" }` — один title «🤖 Агент работает» (и пауза 1 с), дальше плашка
«🤖 JMVCC: управляет агент» и блокировка ввода игрока всю сессию, операции внутри — без title и паузы;
`{ "action": "end" }` — «✔ JMVCC: агент закончил». Ответ begin: `{ "ok": true, "already": false, "idleMs": 60000,
"maxMs": 600000 }`, end: `{ "ok": true, "ended": true }`. Сессия кончается сама через `idleMs` без запросов агента
(любых, и чтения логов), через `maxMs` всего и по `/j remote off`. Между операциями сессии клавиши чата и `/` игрока
работают — чтобы он мог набрать `/j remote off`. begin: 403 `remote_disabled`, 409 `not_connected`.
В `/status` — `control` (true/false) и `controlLeftMs`.

### POST /screenshot
Свёрнутая игра рисует кадры редко: сразу после действия скрин может показать старый кадр — подожди ~0.5–1 с.
Сохраняет `~/.jmvcc/screenshots/<время>.png`, ответ `{ "path": "…" }`.

## Безопасность и видимость

- Перед мутирующей операцией мод показывает игроку title «🤖 Агент работает» и subtitle
  «не трогай клавиатуру и мышь» и **ждёт 1 секунду** — если игрок ещё не предупреждён: нет сессии управления
  (`POST /control`) и прошлая операция кончилась больше 20 с назад. Иначе операция идёт сразу.
- Пока операция идёт (или открыта сессия), в левом верхнем углу HUD висит плашка «🤖 JMVCC: управляет агент», ввод
  игрока в игру не идёт. Без сессии между операциями серии (20 с) — серая «🤖 JMVCC: агент на связи», ввод работает;
  когда серия кончилась (или сессия закрыта) — на 2 с «✔ JMVCC: агент закончил» (action bar игры не трогается).
- Чтение — `GET /status`, `/sessions`, `/logs`, `/screen`, `/inventory`, `POST /screenshot` и команды `/env var list …` — без
  title и блокировки: на 3 с спокойная плашка «🔎 JMVCC: агент получает информацию». `/env var list` при этом
  по-прежнему требует `remote on`, игрока на сервере и не идёт параллельно с другой операцией (409 `busy`).
- Свёрнутое окно не мешает агенту: пока он работает и 10 минут после любого его запроса (даже чтения логов)
  игра не ставит себя на паузу при потере фокуса (миксин на `Minecraft.pauseIfInactive`); меню паузы, открытое
  раньше, закрывается в начале операции. Удержание `attack` копает и без захваченной мыши.
- `/command` и `/deploy` выполняют действия в главном потоке клиента (`MinecraftClient.execute`),
  HTTP-поток ждёт результат.
- Пакеты custom click с id `jmvcc:*` (RPC `jmvcc:rpc`, мягкая остановка `jmvcc:cmd`) шлёт только сам мод. Клик по
  чужому тексту (чат, книга, табличка) или кнопка диалога сервера с таким id не отправляется (миксины на
  `Screen.defaultHandleGameClickEvent` и `CommonDialogAccess.sendCustomAction`): в action bar «клик … не отправлен»,
  в лог игры — предупреждение. Так владельца нельзя заставить кликом вызвать RPC или остановить мир.

## Команды игрока

`/j` и `/jmvcc` — клиентские команды:
- `/j remote on|off` — разрешить или запретить управление. Сохраняется в конфиг и сразу пишет в чат.
- `/j status` — статус, порт, текущая сессия, сколько ошибок.
- `/j logs` — путь к папке логов и последние 5 ошибок.
- `/j token reset` — новый токен (старые клиенты получат 401). `/j token` без аргумента — подсказка.
- `/j build [сек]` — мягко остановить мир: код доигрывает сессии (до `сек`, по умолчанию 90), потом мод сам шлёт
  `/build`. Ход — сообщениями `[JMVCC]` и плашкой с отсчётом; ввод не блокируется. Нет мягкой остановки в коде
  (нет ответа за 3 с) — мод только говорит об этом и подставляет `/build` по клику (Enter — подтверждение), сам не шлёт.
  Код не прислал `ready-to-stop` за таймаут + 10 с — `/build` всё равно (если `#jmvcc status` не говорит, что
  остановку отменили). Сменил мир или мир перезапущен — ожидание кончается, `/build` не шлётся. `сек` — 1..600.
  `#jmvcc build N` уходит в чат мира: без приёмника в коде его видят все. Не работает, пока агент занят (деплой).
- `/j build cancel` — отменить (`#jmvcc cancel`; и остановку, которую начал агент — его деплой вернёт `cancelled`).
- `/j build force` — не ждать: `/build` сразу (идёт ожидание — оно кончается `forced`, деплой агента идёт дальше).
- `/j build status` — спросить код (`#jmvcc status`): идёт ли остановка и сколько сессий в работе.
  `/j status` показывает и локальное состояние остановки.

## CLI `jmvcc client`

Читает `~/.jmvcc/bridge.json`.
- `jmvcc client status`
- `jmvcc client logs [--session <id>|--all] [--errors] [--types a,b] [--since <seq>] [--json]` — по умолчанию
  текущая сессия без чата.
- `jmvcc client send "<text>"`
- `jmvcc client deploy <file.jc> [--no-play] [--wait <сек>] [-O]` — compile → upload (как `compile -u`) → `/deploy` →
  ждать `--wait` (по умолчанию 5) секунд → напечатать события сессии (`error`, `warning`, `critical`, `log`,
  `system` — вывод модуля; ответы сервера `🔔 »`/`✔ »` о шагах деплоя не печатаются).
  Exit-код 1, если деплой не удался или в логах есть error/critical.
  `--graceful [--drain-timeout <с>]` — перед `/build` мягкая остановка (`graceful: true`, шаг `drain` в выводе):
  `drain ✔ 12.3 с (доиграно, таймаут кода 90 с) · build ✔ …`. `--drain-timeout` 1..600. Отмена игроком — `drain ✘ … cancelled: …`, exit 1.
  Старый мод (нет `drain` в `/status`) — ошибка до загрузки модуля, ничего не останавливается.
- `jmvcc client stop [--timeout <с>]` (1..600) — `POST /stop`: мягкая остановка и `/build`, без заливки. Exit 1 — остановка
  отменена или `/build` не прошёл. Нет мягкой остановки в коде — `/build` сразу.
- `jmvcc client screen`, `jmvcc client click <slot> [--right] [--shift]`, `jmvcc client use`, `jmvcc client close`,
  `jmvcc client shot`.
- `jmvcc client button <текст>` — `POST /button`, например `jmvcc client button Возродиться`.
- `jmvcc client items [--all] [--json]` — `GET /inventory`: предметы рюкзака (слоты 9–35) и открытого окна, по
  умолчанию без хотбара, брони и второй руки (там обычно инструменты игрока; `--all` — с ними, иначе внизу «ещё N в
  хотбаре/броне»). Печатает места и id/имя, потом готовые строки для .jc:
  `inline var ITEM_BILLIARD_CUE_BALL = item_raw("H4sI…")  // player_head "Billiard Cue Ball"`.
  Имя константы — как у `jmvcc decompile`: из своего имени предмета (без цветовых кодов, не буквы/цифры → `_`,
  до 40 символов), без него — из id (`ITEM_PLAYER_HEAD`); одинаковые имена — `_2`, `_3`. Одинаковые предметы (тот же
  `raw`) — одна строка со всеми слотами. Предмет на курсоре — место `курсор`. При открытом креативном инвентаре
  его вкладки не показываются (подсказка закрыть его). `--json`: `{ items: [{ constant, line, id, count, name,
  customName, lore, raw, places: [{ in: "inventory", slot, section } | { in: "container", index } | { in: "carried" }]
  }], hidden, container, creative }`.
  Старый мод (нет `/inventory`) — ошибка «обнови jar мода», exit 1.
- `jmvcc client control begin|end` — `POST /control`: серия действий (клавиши, клики, команды, деплои) под одним
  title. Без неё операции и так склеиваются, если между ними меньше 20 с.
- `jmvcc client vars <game|save> [поиск] [--page N] [--raw] [--json]` — переменные мира со значениями: шлёт
  `/env var list page N <game|save> [поиск]` по всем страницам (по 9 строк, сортировка по имени, поиск — подстрока)
  и печатает `имя = значение` из hover_event строк. Значения упрощены: `{type: number, '7.0&Double'}` → `7`,
  текст → `"…"`, `location(x, y, z, yaw, pitch)`, `item(DIAMOND_SWORD x 2)`, словарь `{"k"=1}`; `--raw` — как
  пишет сервер. Длинные значения сервер обрезает сам: `... (+2140)`. Ответ мод помечает `error` (в нём ❌), CLI —
  `system`. Нет переменных — «Переменные отсутствуют или не загружены». Только game и save (line/local не видны).
- Чистка: `jmvcc client send "/env var clear <game|save> [имя]"` — имя ТОЧНОЕ (не префикс; иначе «Переменная с
  именем … не найдена»), без имени — все переменные области («Очистил 32 игровых переменных»). Объявления
  `game var x = 0` после чистки не выполняются заново до следующего `/play`.
- `jmvcc client key <клавиша...> [--ms N]` — `POST /key`, например `jmvcc client key forward sprint --ms 2000`.
- RPC агента (код залит с `client deploy … --rpc`, протокол — llms.txt «Agent RPC»): `jmvcc client call <fn> [args...]`
  (каждый аргумент — JSON, если разбирается, иначе текст; начинается с `[`/`{`, но не JSON — ошибка; отрицательные
  числа — после `--`; `--text` — все как текст, `--file args.json` — JSON-список аргументов из файла), `jmvcc client
  get <var>`, `jmvcc client set <var> [значение] [--text | --file value.json]`, `jmvcc client rpc-list [--json]`; у всех
  `--timeout <с>` (по умолчанию 5). Windows PowerShell 5.1 выкидывает `"` из аргументов (`'[1,"a"]'` → `[1,a]`):
  там `\"`, `--file` или bash.
  Поверх `POST /customclick` (мод не менялся): `jmvcc:rpc` с SNBT
  `{id:"<8 hex>",k:"<ключ>",op:"call",fn:"give",args:"[5]"}`, потом CLI читает `/logs?since=` (раз в 150 мс) до строки
  `log` `jmvcc:rpc <id> ok [<json>]` / `jmvcc:rpc <id> error <текст>`. Печатает значение JSON (`ok [6]` → `6`); ошибка,
  ответ не JSON-список (обрезан / искажён) и нет ответа за таймаут — exit 1.
  Ключ `k` — `~/.jmvcc/rpc-key` (создаёт первая сборка с `--rpc`: compile / check / trace / client deploy; та же
  строка вшита в приёмник): пакет без него (клик владельца по чужому тексту с `click_event` custom — ванильный клиент
  шлёт тот же пакет) получает `error bad key` и ничего не зовёт. Заливать и звать — с одной машины.
  Каждый вызов — мутирующая операция мода (title и пауза 1 с, если нет `client control begin`).
- Ответ 403 `remote_disabled` CLI печатает как есть, с подсказкой «попроси игрока включить: /j remote on», exit 3.

## Deviations

### CLI (`jmvcc client`) и `log(...)`
- **Exit 2** — мост недоступен: нет или битый `bridge.json`, порт не отвечает (если процесс `pid` из
  bridge.json мёртв, CLI так и пишет: «bridge.json устарел»), 401. Контракт задавал только 1 и 3.
- `deploy` перед `/deploy` вызывает `GET /status` (выключено управление → exit 3, игрок не на сервере → exit 1,
  до загрузки модуля) и запоминает последний `seq` текущей сессии. Если `/deploy` вернул другую `session`
  (мир запущен заново), события печатаются с начала новой сессии, иначе — с `seq` больше запомненного.
  Печатаемые типы: `error`, `warning`, `critical`, `code_notice`, `log` (`code_notice` добавлен — это
  нераспознанная ошибка кода). Exit 1 — как в контракте: `ok: false` или `error`/`critical`. При `ok: false`
  пауза `--wait` пропускается.
- `logs --errors` = `types=error,critical,warning,code_notice`. `--errors` и `--types` складываются.
  `logs --all` — `GET /sessions` и `GET /logs` по каждой (без `--json` — с заголовком сессии).
  Внизу печатается `последний seq N (дальше: --since N)`.
- `use --off` — предметом во второй руке (`hand: "off"`).
- `send`: Git Bash превращает аргумент `/build` в `<корень MSYS>/build` (`C:/Program Files/Git/build`, у scoop —
  `C:/Users/u/scoop/apps/git/current/build`). Только при `MSYSTEM` в окружении CLI узнаёт корень (`cygpath -m /`,
  запасной вариант — `EXEPATH` без `\bin`) и срезает ровно его. Если после корня есть `\` или `;` (MSYS принял
  команду со `:` и `/`, например со ссылкой, за список путей) — восстановить нельзя, ошибка с подсказкой
  `MSYS_NO_PATHCONV=1` или `//build`. Команду вида `/a:b` MSYS превращает в `a:b` без корня — её CLI не узнаёт.
- `JMVCC_UPLOAD_DOMAIN` (env; старое имя `JMCC_UPLOAD_DOMAIN` тоже работает) подменяет хостинг модулей `https://m.justmc.ru` — для тестов с мок-сервером.
  Загрузка модуля (`deploy`, `compile -u`) ждёт ответа хостинга не больше 30 с.
- **Ошибки без клика**: `error`/`warning`/`critical` без `block` (нет клика `/editor tp`) CLI показывает как
  `system` (исходный тип — в поле `rawType`, видно в `--json`), в `deploy`, `logs --errors` и `--types error,…`
  их нет и деплой они не валят. Настоящая ошибка кода всегда с кликом, а без него это `⚠` — значок ранга в
  рассылках вида «🗡 » Admin X ⚠ заблокировал…» — или «❌ Ошибка …», присланная игроком в личку. Счётчик `errors`
  в `GET /sessions` и `/j status` считает мод — там такие события пока остаются ошибками.
- `log(a, b, …)`: если первый аргумент — текст, маркер приклеивается к нему и части идут через пробел
  (`merging=SPACES`, как у `player::message`). Если первый аргумент не текст (`log(x)`), маркер — отдельная
  часть и пробелы вставляются явно (`merging=CONCATENATION`), иначе после маркера был бы пробел. Больше
  18 частей — ошибка компиляции. `log` только отдельной строкой (как значение — ошибка), без именных аргументов.
  `function log(...)` перекрывает встроенный (с предупреждением) в своём файле и в файлах, которые его
  импортируют. В файлах, которые импортирует он сам, `log(...)` остаётся встроенным: функцию импортирующего
  файла из импортированного не вызвать ни под каким именем (`foo(...)` там — «Неизвестная функция»), так что
  раньше такой код не компилировался и совместимость JSON не задета.

### Мод (`client-mod`)
- **Версии сборки**: Loom 1.19.3 и Gradle 9.8.2 (а не 1.17.x / 9.5.x) — так в ветке `26.2` fabric-example-mod;
  Minecraft 26.2, Loader 0.20.1, Fabric API 0.161.0+26.2.
- **Имена окон** — моджанговские (`getClass().getSimpleName()`): сундук/меню — `ContainerScreen`, а не
  `GenericContainerScreen` (это имя из Yarn). Для окна без слотов `slots: []`, `playerSlotsFrom: null`.
- **Сессии**: при входе на сервер новая сессия начинается событиями `session/start` (`reason: join`) и сразу
  `session/join` (`offlineMs` — сколько был оффлайн, нет поля, если это первый вход после запуска игры).
  Переподключение к тому же серверу быстрее 5 с и повторный JOIN без выхода (смена мира через конфигурацию)
  **продолжают** текущую сессию (`session/join`, новой сессии нет). При выходе из игры — `session/leave` с
  `reason: client_stopping`. Если две сессии стартуют в одну секунду, у второй id с суффиксом `_2`.
- **Событие**: поле `json` (исходный компонент) пишется для всех типов, кроме `chat` (экономия места).
  Тип `session` входит в `types` по умолчанию; `types=all` — всё, включая `chat`.
- **`/logs`**: `limit` по умолчанию 1000 (максимум 10000). С `since` — первые `limit` событий после `since`,
  без `since` — последние `limit`. `last` — seq последнего отданного события; если событий нет — `since`
  (или максимальный seq сессии). Нет текущей сессии — `{ "session": null, "events": [], "last": 0 }`.
  Неизвестный id — 404 `no_session`.
- **Ошибки API** сверх контракта: 400 `bad_request` (нет полей, не JSON, `!`-проверка идёт первой; текст длиннее
  256 или с переводом строки/управляющими/`§` — сервер кикнул бы), 400 `bad_slot`, 404 `not_found`,
  401 `unauthorized`, 500 `internal`, 503 `main_thread_timeout` (клиент не выполнил действие за 10 с — игра
  зависла или грузит мир; повторить позже). `url` в `/deploy` — только `http(s)://` без пробелов (≤ 300 символов).
  Поля тела строго типизированы: `slot` — целое число, `button`/`hand` — строки, `shift`/`play` — `true`/`false`;
  другой тип — 400 `bad_request`; `null` у необязательного поля = поле не задано.
- **`/click`**: порядок проверок — поля (400) → `remote_disabled` (403) → `not_connected` (409) → `no_screen` (409,
  до паузы в 1 с) → `busy` → `bad_slot` (400).
- **`/deploy`**: у каждого шага есть `ms`; у `dev` — `changed` (сменился ли мир за 5 с; `ok: true` в любом
  случае); у `module` — `message` (текст сервера). Неудача: `ok: false`, `error` (`timeout`, `module_error`,
  `remote_disabled`, `not_connected`, `main_thread_timeout`, `internal` — сбой мода) и `message`; HTTP 200,
  список `steps` есть всегда. Между шагами проверяются remote и подключение —
  `/j remote off` посреди деплоя обрывает его. Признак ошибки модуля (формат сервера неизвестен): событие
  `error`/`critical` или системное сообщение с `❌`/«Ошибка»/«ошибк»/«не удалось»/«Неверн»/«не найден».
  Успех засчитывается только по **системному** сообщению с серверным префиксом «значок »»: `✔ » Модуль …
  успешно импортирован` и `🔔 » Мир запущен в режиме игры` (строка игрока в чате с тем же текстом не подходит;
  по тому же признаку начинается сессия `world_started`).
- **Классификация**: метка времени `[hh:mm:ss] ` срезается у всех сообщений. Порядок: `log` (маркер U+2063) →
  `chat` (`[!] Ник: …`, `[⭐] …: …` — 1–3 символа в скобках и двоеточие, `⏵ …`, `<Ник> …`) → `critical`
  (`‼`, «Критическ» в первой строке) → `error` (`❌`, «остановило строку кода») → `warning` (`⚠`,
  «Предупреждение» в первой строке) → `code_notice` (есть клик `/editor tp`) → `system`. Так игрок, написавший
  «❌ Ошибка» в глобальный чат, остаётся `chat`. У ошибок `text` очищен от рамки (пробелы по краям строк,
  U+200C, пустые края).
- **`/status`** дополнительно отдаёт `version` мода. `server` для одиночной игры — `"singleplayer"`.
- **`/use`** отвечает ещё `result` (InteractionResult клиента). **`/close`** — `closed: true|false`.
- **`/screenshot`** не мутирующая (без title и паузы, работает и при `remote off`) — иначе title попал бы на снимок.
- **«Агент закончил»** держится 2 с: через 40 тиков action bar очищается пустым сообщением (если сервер в эти
  2 с прислал свой action bar, он тоже сотрётся).
- **Ввод игрока**: пока агент работает и окно не открыто, каждый тик отпускаются все клавиши
  (`KeyMapping.releaseAll`), после — состояние клавиш восстанавливается.
- `bridge.json` удаляется при выходе из игры (если `pid` в нём наш) — CLI сразу видит, что игра закрыта.
