# jmvcc decompile — модуль JSON → JustCode

```
jmvcc decompile export.json              # → export.jc рядом (или export.decompiled.jc), сразу проверка круга
jmvcc decompile export.json -o main.jc   # предметы — в main.items.jc (import в начале main.jc)
jmvcc decompile "https://…/handlers/<id>?token=…" -o main.jc   # модуль по ссылке (/module в игре, ссылка одноразовая)
jmvcc decompile export.json --no-verify  # без сравнения (компиляция всё равно проверяется)
jmvcc decompile export.json --allow-diff # код выхода 0 и при различиях
```

Вход — любой модуль `{handlers: [...]}`: выгрузка из игры или результат `jmvcc compile` (с `-O` и без).
Выход — JustCode, который `jmvcc compile` собирает обратно в тот же JSON (после нормализации, ниже).
Команда печатает заметки (что выражено не один в один — в `.jc` это комментарии `// decompile: ...`), список
пустых перечислений, которым подставлено первое значение, и результат круга: «compile даёт тот же JSON» или
список различий — **эти данные при заливке потеряются**.

Код выхода: 0 — круг без различий, 2 — есть различия (`--allow-diff` → 0), 1 — ошибка (не прочитать, не JSON,
результат не компилируется, файл не перезаписан).

Куда пишет: `-o <путь>` или `<имя>.jc` рядом с JSON. Файл `.jc`, написанный не decompile (нет шапки
`// Декомпилировано: jmvcc decompile`; старая шапка с `jmcc decompile` тоже узнаётся), не перезаписывается никогда: без `-o` тогда пишется `<имя>.decompiled.jc`,
с `-o` — ошибка; `--force` — перезаписать. Обычный цикл `compile main.jc → decompile main.json` исходник не трогает.
Константы предметов `item_raw` (base64 на тысячи символов) — в `<имя>.items.jc` рядом, основной файл начинается с
`import "<имя>.items.jc"`: его можно читать целиком и грепать.

Ссылка: 401/403/404 от api.creative.justmc.io — почти всегда истёкшая одноразовая ссылка, CLI так и пишет; новая — `/module` в игре.

## Форма вывода

- Действия — с именованными аргументами: `player::message(messages = ["a"], merging = "CONCATENATION")`.
  Имя — своё (JMVCC, data/aliases.json), как в документации: `player::give_item`, `world::spawn_entity`,
  `code::catch_error`; имя с выбором по виду получателя — когда получатель записан именованным аргументом
  (`variable::sort(list = l)`, `variable::length(map = m)`: компилятор берёт ветку по имени аргумента, круг точный).
  `.remove` / `.random` (только через точку) и `put_map_value` — серверным именем.
  Перечисление, равное умолчанию компилятора, не пишется.
- Условия — `if (...) { } else if (...) { } else { }`, `is_inverted` → `!`; сравнения `if_variable_equals/less/...` с
  одним значением — `a == b`, `a < b`; `repeat::while(...)`, `select::*_by_conditional(...)`.
- Циклы — переменные цикла явными аргументами: `repeat::on_range(variable = i, start = 0, end = 3) { }`;
  `stop_repeat` / `skip_iteration` внутри цикла — `break` / `continue`.
- `x = v` (set_value), `x += n` / `x -= n`, `out = obj::f(...)` для действий с результатом.
- Вызовы своих функций — `name()`; процесс — `name()`, если режимы как у компилятора
  (CURRENT_TARGET + COPY), иначе `code::start_process(...)`. `return` в функции, `break` вне цикла,
  `code::end_thread()` в цикле и в функции (там `break` значит другое; алиас без предупреждения).
- Переменные объявлены группами (`var a, b, c`, строка до 100 символов): `game var` / `save var` в начале файла,
  `var` / `line var` в начале обработчика.
  Необычные имена — в обратных кавычках: ``process `#DNBS#DONOTTOUCH#PLAY`()``, `` `Меню пластинок`() ``.
- Имя функции, которое JustCode не объявит (фабрика `item`, старая математика `floor`, `$` в имени), → `fn_item`,
  `fn_a_b` с заметкой: в JSON имя станет другим (вызовы из игры по старому имени не найдут) — круг это покажет.
- Текст: `%var_local(x)` → `${x}`; `$` экранируется. `%math(...)` в числе → выражение (`speed * 7`), если
  компилятор соберёт ту же строку; иначе `number_raw("%math(...)")`.
- Предметы: JSON-строку компилятора — `item("stone", "&bName", count = 2, lore = [...])`, если фабрика
  даёт ту же строку; бинарный NBT из игры — константой `inline var ITEM_КИЙ = item_raw("H4sI…")  // stick "Кий"`.
  Имя константы — из названия предмета (`ITEM_POKER_FACE`), без названия — из id (`ITEM_PLAYER_HEAD_2`).
- Метаданные функций из игры — `function_info(description = [...], icon = ITEM_..., hidden = true)` первой строкой
  тела (компилятор пишет их в `values` обработчика). Параметры функции из игры (`parameters`) не пишутся — заметка.
- Аргумент действия, которого нет в реестре (старый блок из игры: `player_play_sound.source`), — значением `*_raw`:
  `source = enum_raw("RECORD")`, `var_raw(...)`, `text_raw(...)`, `number_raw(...)`, `item_raw`-константа.
- Хвосты длинных строк `jmcc.fN` (выгрузки старых версий или `--max-line`; сейчас строки не режутся) вставлены на место единственного вызова. Хвост с `return` (или `continue` вне
  своего цикла) — только если вызов последний в функции (верхний уровень или последний блок, не в цикле): из хвоста
  `return` возвращает только из него, вставленный — из всей функции. Иначе хвост остаётся функцией `jmcc_fN`;
  так же — если вставка ломает раскладку строки (`return` / `line var`, ошибка line-too-long). Выгрузка с `jmcc.fN` проверяется лимитом прежних версий (43), даже без лимита у
  компиляции: иначе вставленный хвост увидел бы `line var`, записанную до вызова (на сервере в хвосте она пустая).
  Свежий код без `jmcc.fN` проверяется без лимита; лимит задаёт только env `JMVCC_MAX_LINE` (у decompile флага
  нет; `--max-line` — у compile/check/trace/client deploy).
- Временные `jmcc.N` компилятора → `jmcc_tN` (имена `jmcc.N` раздаёт компилятор); в сыром тексте
  (`number_raw`, `text_raw`) — тоже: раньше `%var_local(jmcc.6)` оставался, а код писал `jmcc_t6` (две разные
  переменные; нормализация прятала это — теперь видно).
- Индексы (src/core/decompiler/IndexSugar.ts): `x = l[i]`, `l[i] = v`, `x = m["k"]`, `m["k"] = v` и
  `l[i] += x` (`-= *= /= %=`) вместо get/set_list_value, get/set_map_value; вложенные `x = l[0][1]`,
  `l[0][1] = v`, `m["k"][0] += 1` — если временные между уровнями больше нигде в модуле не встречаются. Только там,
  где компилятор выберет то же действие: вид переменной (словарь/список/текст/число) считается по коду выше тем же
  анализом (src/core/jmvcc/IndexKinds.ts); иначе — вызов как раньше (`variable::get_map_value(map = m, key = [k])`).
  `l[i] = value::x` — вызовом (компилятор пишет его через временную), `m[k] = value::x` — индексом.

## Фабрики «как в JSON» (добавлены для decompile)

| Фабрика | JSON |
|---|---|
| `item_raw("H4sI…")` | `{type: item, item: "<строка как есть>"}` — base64 gzip NBT из игры (проверяется распаковкой), `AAAAAAAAAAA=` (пусто) или JSON `{"id": ...}` |
| `text_raw("<red>a", parsing = "plain")` | `{type: text, text, parsing}`; режимы legacy, plain, minimessage, json (обычная строка — без поля = legacy) |
| `number_raw("%math(%length(l)-1)")` | `{type: number, number: "<строка как есть>"}` |
| `var_raw("x", "game")` | `{type: variable, variable: "x", scope: "game"}` без объявления — когда одно имя в обработчике и local, и game (код, собранный в игре), или имя с `$` |
| `enum_raw("RECORD")` | `{type: enum, enum: "RECORD"}` без проверки |
| `sound("id", 1, 2, variation = "", source = "RECORD")` | поля `variation`, `source` (без них в JSON их нет) |
| `function_info(description, icon, hidden)` | `values` обработчика: `description` (список текстов), `is_hidden`, `icon` |

Значение `*_raw` можно передать аргументу действия, которого нет в data/actions.json, — оно пишется как есть;
обычное значение в таком аргументе — ошибка «Неизвестный аргумент» (опечатки ловятся как раньше).
`particle("ELECTRIC_SPARK")` — id частицы целиком в верхнем регистре (как в выгрузке) пишется как есть, иначе — в нижнем.

## Что считается одинаковым (нормализация круга, src/core/decompiler/Normalize.ts)

- порядок обработчиков, `position`, порядок ключей и аргументов действия;
- хвосты `jmcc.fN` / `jmcc_fN` — вставлены на место вызова по тому же правилу, что в decompile (хвост с `return` —
  только последним в функции, иначе остаётся функцией, и неравенство такой вставки видно); оставленный `jmcc_fN` = `jmcc.fN`;
- метаданные функций/процессов сравниваются: пустое описание (и хвост пустых строк), пустая иконка (`{}`,
  `AAAAAAAAAAA=`), `is_hidden` FALSE / нет = одно и то же; `is_hidden` в `values` = `is_hidden` компилятора;
- пустой слот `{}` = отсутствующий аргумент; хвост `{}` в списке; пустой список; пустой map
  (`start_process.args = {type: map, values: {}}` из игры);
- блок `empty` (пустая клетка в игре) — не пишется;
- пустое перечисление = умолчание компилятора (первое значение, у boolean — `defaultBooleanValue`, иначе TRUE).
  Для boolean так считает сервер (docs/semantics.md); для остальных перечислений это **допущение, на сервере не
  проверено** — CLI печатает, каким аргументам что подставлено (в бильярде 70: merging = SPACES, comparison_mode =
  EXACTLY, local_variables_mode = DONT_COPY, ...);
- одно значение в аргументе-списке (старые блоки) = список из одного (компилятор всегда пишет список);
- умолчания сервера: `text.parsing` нет = legacy, `sound.variation` нет = "", `sound.source` нет = MASTER,
  `is_inverted` нет = false, `selection: "null"` у game_value = default, выбор действия `default` = без выбора,
  `minecraft:` в id звука, число строкой (`"2.0"`) = число;
- временные (`jmcc.N`, `jmcc_tN`; переменные и `%var_local(...)` в текстах) — с точностью до переименования:
  взаимно однозначно по первому появлению (обработчики по ключу и тексту без имён временных). Сахар индексов
  заводит новые временные с другими номерами; `jmcc.4` и `jmcc_t4` в одном модуле — разные переменные;
- `values` у `conditional` (компилятор дублирует в них внешние значения, игра — нет);
- пустые события (компилятор их не пишет).

## Проверка

```
npx tsc --build src && node scripts/roundtrip.js [--only <подстрока>] [--keep <папка для .jc>] [выгрузка.json ...]
```
Корпус: docs/recipes*.jc, bench/**/*.jc, examples/*.jc, D:\justmc-games\*\main.jc — каждый скомпилирован без `-O`
и с `-O`, затем decompile → compile (без `-O`) → сравнение. Выгрузки из аргументов — с файлом предметов.
Тесты: `npx jest decompile` (в т.ч. модуль «как из игры»: else без if, пустой слот, метаданные, хвост с return в
цикле, source звука; бильярд, если есть D:\justmc-games\billiard\export.json).

Итог 2026-11-03 (индексы и группы объявлений): корпус — 279 прогонов из 279, бильярд — 0 различий, main.jc
1264 → 993 строки (86 239 → 81 538 байт). Раньше: корпус — 274 прогона из 274; бильярд (export.json) — 0 различий (source звука — `enum_raw`,
метаданные — `function_info`, хвост jmcc.f5 с return, вызванный из цикла castball, — функцией `jmcc_f5`).

## Ограничения

- Аргумент вне реестра со значением, у которого нет формы `*_raw` (место, вектор, звук, список, ...), — пропущен с
  заметкой, круг показывает различие.
- Словарь-литерал с данными, пустой слот внутри списка, значение неизвестного типа — комментарий, различие.
- `else` без условия перед ним и условие без тела — выписаны закомментированными, различие.
- Параметры функций из игры (`parameters`) — не пишутся, различие.
- Пустые не-boolean перечисления — первое значение (не проверено на сервере, см. выше).
