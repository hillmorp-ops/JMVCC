# JustMC: код на JustCode

Компилятор JMVCC лежит в `D:\jmcc` (в PATH его нет):
- Git Bash / sh: `/d/jmcc/jmvcc <команда>` (шим, передаёт `event<...>` как есть);
- PowerShell / cmd: `D:\jmcc\jmvcc.cmd <команда>`; там `event<...>` бери в кавычки или пиши голое имя: `sig player_death`.
- Старое имя `jmcc` (`/d/jmcc/jmcc`, `D:\jmcc\jmcc.cmd`) — псевдоним, работает так же.

## Перед первой строкой кода
Прочитай целиком `D:\jmcc\docs\llms.txt` — синтаксис, ловушки, рецепты, проверенные факты о сервере.
Не угадывай имена: `jmvcc search <слова>` и `jmvcc sig <имя>`. Готовые рецепты: `D:\jmcc\docs\recipes*.jc`.

## Цикл
1. Пиши `main.jc` в папке игры пользователя (не в `D:\jmcc`, если тебя не просили менять сам компилятор).
2. `jmvcc check main.jc` — все ошибки сразу; исправляй по «Возможно: …» буквально. `jmvcc trace main.jc` — сверь с замыслом.
3. В игру (если запущен Minecraft с модом JMVCC Bridge — `jmvcc client status`):
   `jmvcc client deploy main.jc` → читай вывод: ошибки сервера, `log(...)`, сообщения модуля. Чини и повторяй.
   Меню/клавиши/кнопки для проверки: `jmvcc client use | screen | click | key | button | shot` (D:\jmcc\docs\bridge-api.md).
   Серию действий в игре (клавиши, клики, команды) оборачивай: `jmvcc client control begin` … `jmvcc client control end`
   — игрок видит одно «Агент работает» вместо десятка. Логи, `vars`, `status` не управляют клиентом, им не нужно.
   Головы и особые предметы (свои текстуры, /hdb, предметы с NBT) не выдумывай: попроси пользователя «набери нужные
   головы (/hdb) в инвентарь и отпиши», потом `jmvcc client items` (`--all` — если они в хотбаре) и вставь готовые
   строки `inline var ITEM_… = item_raw("…")` в .jc (много — в `<имя>.items.jc` + `import`).
4. Отладка: `log("x = $x")` — строки попадают в логи моста (`jmvcc client logs`).
   Значения всех переменных мира сейчас: `jmvcc client vars game|save [подстрока имени]` (`имя = значение`, все
   страницы `/env var list`; `--json`). Сбросить переменную: `jmvcc client send "/env var clear game <точное_имя>"`.
   `/env var clear save` БЕЗ имени стирает все сохранённые данные мира — только если пользователь сам попросил.

## Ловушки, которые ломают код молча (проверено на сервере; подробности — llms.txt)
- `var` в функции — ОБЩАЯ с вызывающим (и параметры тоже); черновые значения в функциях — `line var`.
- Ошибка сервера обрывает остаток СТРОКИ кода, включая строку того, кто вызвал функцию. Рискованное — в `process`.
- Блоки и мобы переживают `/play` и `/build`, переменные game — нет: NPC/стойки создавай один раз
  (`save var npc; npc ??= ""; if (!world::has_entity([npc])) { ...; npc = value::uuid<last_entity> }`).
- Имена — как в llms.txt «JMVCC names»: `l.append(x)`, `l.length()`, `l.sort()`, `m.get(k, 0)`, `player::give_item`; одно
  слово выбирает действие списка / словаря / текста по тому, что в переменной (создай её выше). Предупреждение
  `kind-guessed` (вид не виден, взят список) — поправь на точное имя из текста; серверные имена тоже работают.
- Параметр, по которому метод выбирает действие, — с типом: `function f(m: map, t: text, l: list)` (вызов с другим видом —
  ошибка). Без типа вид берётся из вызовов; `kind-mixed` (вызовы с разными видами → проверка в рантайме) — укажи тип.
- Неприсвоенная переменная = число 0: `set_map_value` на ней — ошибка, `l.append` — тихо НИЧЕГО (список не
  появится); сначала `m ??= variable::create_map_from_values([], [])`, `l ??= []`.
- `value::event_block_type` = `"minecraft:id[состояние]"`, `==` с голым id всегда ложь — `event_block_equals`.
- В потоке без цели (NO_TARGET) действия без `<селектора>` идут на выбранных (`select::...`), читать их — `value::x<current>`.
- Поток умирает со своей целью (игрок вышел — его цикл встал посреди). Мировой цикл — в верхнем коде или NO_TARGET.
- Повторный `/play` снова запускает `player_join`, старый цикл игрока живёт дальше (два цикла): ставь поколение
  `%player%_loop = value::timestamp` и `if (%player%_loop != my) { code::stop_repeat() }` в цикле.
- Изменение списка внутри `for_each` по нему же обрывает цикл. Списки копируются при присваивании.
- Две функции с одним именем выполняются ОБЕ. `code::controller_async_run` не работает.
- mm:ss — `std::mmss(ms)` (одно действие), не самописная функция.
- `/build` и деплой рвут все потоки сразу. Игра с долгими сессиями (ковка с wait, раунд, забег) — вход каждой
  новой сессии в `std::session("имя") { ... }`, возврат ресурсов / save var — в `event<jmvcc_stop> { ... }` (без wait).
  Метить только ВХОД (клик, старт раунда), не каждую функцию; процесс изнутри — `local_variables_mode = "COPY"`.
  Флаг: взял — `%player%_x = 1`, награда только `if (x == 1) { x = 0; выдать }`, jmvcc_stop возвращает под тем же
  флагом (он идёт при каждом выходе и может прийти дважды).
  Подробно — llms.txt «Graceful stop».
- Отладка в РАБОТАЮЩЕМ мире без передеплоя: пометь `rpc function f(...)` / `rpc game var x`, залей
  `client deploy main.jc --rpc` и зови `client call f 5`, `client get x`, `client set x 100`, `client rpc-list`.
  Без `--rpc` слово rpc ничего не меняет — релиз заливай без флага. JSON-аргументы с кавычками — из bash или
  `--file args.json` (PowerShell выкидывает `"`). Подробно — llms.txt «Agent RPC».
- Компилятор не режет строки (лимита 43 нет: сервер выполнил плоскую строку события из 1002 блоков, server-check-20b;
  функция из 95 и процесс из 93 блоков с вложенными if/else/repeat, ранним return и line var после 43-го блока — server-check-21): не дроби событие
  на функции ради длины — вызов стоит действий, а функция делит `var` вызывающего. Функции — для повторов и читаемости.
  Старая разбивка на `jmcc.fN` — только с `--max-line 43` (не нужна).
- `%%` в тексте — не экранирование, не пиши.
- Фазы и состояния — `enum Phase { LOBBY, GAME }` (числа, опечатка = ошибка компиляции, -O даёт дешёвое сравнение),
  состояние игрока — `struct Run { hp = 20 }` + `game var %player%: Run` (`%player%.hp` — это `%player%_hp`). Объявление
  умолчаний НЕ ставит: `%player% = Run()` в player_join (save — `??=`). В JSON ровно ручной код. llms.txt «Enums and structs».
- Ошибки — `try { } catch (e) { }` (e — текст: id ошибки сервера или сообщение `throw("...")`), разбор по значению —
  `match (x) { 1, 2 -> ...  Phase.GAME -> { }  else -> ... }` (ветки с новой строки, стрелка `->`; switch/finally нет).
  match — оператор, не выражение: `1 -> label = "one"`, а не `var label = match ...`. Функция с `code::end_thread()`
  из тела try выходит только из try (`try-end-thread`) — верни флаг и выйди в самом теле. llms.txt «Errors and branching by value».

## Цена кода (замерено; числа — llms.txt, подробно — dev/research/*-bench.md)
- Бюджет — в % `value::cpu_usage` (читай на месте, не в тиковом цикле): перевод мс → % между сессиями плывёт ×1.8.
  Тяжёлое — ≤ ~3 мс за тик, пики ≤ 80%.
- `==` / `!=` ≈ 8 действий (equals со списком), `>` `<` ≈ 1, `variable::number_in_range(x, a, a, "INCLUDE_ALL")` ≈ 1.5:
  в горячих циклах числа сравнивай без `==`. `x == 1 || x == 2` → `variable::equals(x, [1, 2], compare_type = "ANY")`.
  Диспетчер по ключу — список (`LV[k]`, `code::call_function(LF[k])`) или словарь, не цепочка `==`.
- Словарь: `m[k]` / `m[k] = v` — дешёвые (get_map_value_single ≈ 1.2 / put_map_value ≈ 1.8, компилятор так и пишет);
  `m.get_map_value(k)` / `m.set_map_value(k, v)` со списком ключей в 4–6 раз дороже — только для нескольких ключей.
  `l.append` (list_append_value) ≈ 7.5 — несколько значений одним `append([a, b])`; поиск — `l.index_of(x)` + `> -1`.
  Чтение списка из словаря/переменной копирует его (≈0.25 мкс на элемент) — не тяни большие списки каждый тик.
- Вызов функции ≈ 2, аргументы + return ещё ≈ 7. `start_process` выполняет процесс сразу, до первого `wait`.
  `repeat::while` со счётчиком вдвое дороже `multi_times` / `for_each`. Процесс на объект лишь ≈ на 20% дороже цикла
  по спискам; спящий процесс бесплатен — `wait(5)` / `wait(20)`, где каждый тик не нужен.
- Дисплеи: spawn ≈ 40 мкс, удаляй пачкой (select списка uuid + `entity::remove()` + reset); текст — самое дорогое
  изменение (меняй, когда значение поменялось); матрица в 6–8 раз дороже scale / translation / rotation.
- Карты: шаблон — в тех же чанках, что и арена (прямо над/под ней): копия в чужой чанк +5 мс на каждый вызов.
  До ~150 блоков — только разница `set_block(тип, список, update_blocks = true)`, больше ~1000 — `clone_region`.
  В одном `set_block` с update_blocks = true ≤ 3000 мест (лишнее молча теряется). Копия с воздухом — только с якорем
  (не-воздух, не cave_air, в min-углу шаблона), иначе `clear_region` + копия без воздуха. Копия 8192 клеток каждый
  тик ≈ 25% cpu; `clone_region` — 1–2 за тик.

## Делай красиво (владелец проверяет глазами, «работает» — мало)
- Постройки (дом, арена, декор, лобби) — НЕ импровизацией в коде, а строителем `D:/jmcc/builder` (гайд —
  `builder/GUIDE.md`, рецепты деталей: люки, цепи с фонарями, углы крыш из ступенек, полублоки): скрипт `.build.mjs` →
  `node builder/cli.mjs build` (проверка состояний + предупреждения физики: опора, трава под блоком станет землёй,
  гравий упадёт) → `screenshot` с 3 ракурсов, посмотри сам → `preview` для владельца (живой 3D) → `export-jc --at x,y,z`
  → импорт в игру (`import "<файл>"`, вызов `build_<имя>()`). Не нашёл Minecraft — `--minecraft <папка или .jar>`.
  Улучшить ГОТОВУЮ карту: `jmvcc client export -- x1 y1 z1 x2 y2 z2 --name map` (владелец в /build или /play) →
  `b.load('map.json')` в скрипте → правки → `export-jc` ставит только разницу (GUIDE «Improving an existing map»).
Сначала представь, что видит игрок ОТ ПЕРВОГО ЛИЦА со своего места, потом пиши. Уже забраковано как «на отъебись»:
легенда «какой блок что значит» сбоку от поля, цветные блоки вместо цифр, частицы в фиксированной точке над объектом
(сверху их не видно), поле, до дальних клеток которого не дотянуться и не разглядеть.
- Информация — прямо на объекте: текст лежит на верхушке блока (text_display плашмя), цифры и значки окрашены сами
  (`&#RRGGBB`, потом `&l`), состояние видно формой (закрытое — полублок, открытое — полный блок).
- Значки — символы сервера: проверены на дисплеях ⚑ ☠; остальные бери из `/symbols 1..8` в игре, эмодзи по памяти
  не вписывай.
- Отклик — там, куда игрок смотрит: частицы на грани блока, по которой кликнули; свой звук на каждый исход.
- Обзор и досягаемость: всё поле видно под нормальным углом и до любой клетки достать — площадка обзора с юга +
  `player::set_attribute(16, "PLAYER_BLOCK_INTERACTION_RANGE")` (вживую в сапёре дотянулось ~14 блоков); туда же
  возвращать: `set_spawn_point` не сработал — только телепорт в `player_respawn` после `code::wait(1)`.
- Управление — выжимай механики, а не предметы в хотбаре: WASD через `event<player_input_event>` (+ заморозка ходьбы
  атрибутами или камера сверху через наблюдателя — рецепты в llms.txt «Look and feel»). Прежде чем выбрать схему, поищи
  (`jmvcc search input|key|camera|spectate|vehicle|steer`) и прикинь 2–3 варианта; «4 предмета в хотбаре» и «кликни
  цифру» — отъебись-решения.
- Красиво ≠ тяжело: эффекты только по событию (клик, удар), без частиц и дисплеев каждый тик; HUD — раз в секунду
  одним мировым циклом.
- Чат — худший канал, не сыпь туда всё подряд:
  - топы — табло из text_display в мире (или головы игроков с ником и описанием в меню сундука);
  - уведомления (куплено, не хватает, твой ход, рекорд) — экшнбар + звук, РАЗНЫЙ для хорошего и плохого;
    большие события (победа, смерть) — title; объявления «X начал игру» — табло/экшнбар, не чат;
  - пачка инфы одному игроку (правила на входе, итог) — блок в рамке: сверху и снизу `&8&m` + ~50 пробелов (сплошная
    линия, проверено; ━ ─ ▬ дают швы), каждая строка окрашена, заголовок `&#RRGGBB&l`, отступ двумя пробелами.
    Должно выглядеть как интерфейс, а не будто кто-то написал в чат.
- Одно поле на всех («один играет, остальные смотрят») — запасной вариант. Для одиночных игр (змейка, сапёр, кликер,
  паркур на время) лучше плоты: каждому игроку свой участок, выдаётся при входе (слот в сетке, свободные — save-список),
  строится по шаблону, при выходе всё подчищается (блоки, сущности по uuid). Перезаход ради «новой загрузки» участка
  не даём (кулдаун на повторный вход/рестарт). Мир по рангу больше пола (Star: 768×768) — плоты могут стоять вне пола
  на своей платформе. Пока идея владельца на будущее, рецепта нет: спроси, если делаешь такую игру.
- На входе — 2–3 строки: цель, управление (ЛКМ/ПКМ/предмет), рекорд; рестарт — предметом в хотбаре.
- Образцы «как надо» — `D:\justmc-games\minesweeper\main.jc` и `snake\main.jc`. Кликер там же — старый (висит на
  y=63, топ в чат): координаты и вид оттуда не копируй.
- Перед «готово»: деплой → `jmvcc client shot` → открой png и проверь: поле в кадре, цифры читаются, частицы видны.
  Скрин — для самопроверки, не как результат. Рецепты и точные числа — раздел «Look and feel» в llms.txt.

## Мир: сначала измерь, потом строй
- Права игрока (размер мира, модули, ресурс-пак, WorldEdit) — `D:\jmcc\docs\justmc-privileges.md`; владелец — Star.
  Команды мира (/world, ресурс-пак, /env var, /symbols) — `D:\jmcc\docs\justmc-world-commands.md`.
- Не придумывай координаты пола: измерь (рецепт в llms.txt, «Look and feel») или спроси. У владельца пол — 32×32
  (x,z от -16 до 15), верх y=3, за краем пустота. Строй на полу, не в воздухе; поле игры — с запасом 2 блока от края,
  где бегают (арена, змейка, паркур) — стенка/барьер по краю.
- Никогда не телепортируй игрока туда, где под ним нет блока (так уже убили владельца).
- Сущности (дисплеи, мобы) переживают /play: uuid в save-список, удалять при рестарте и старте мира. Блоки — просто
  перестраивать тем же кодом; старую постройку (перенос игры) стереть один раз под save-флагом (`clean_old` в сапёре).

## Нельзя
- Сообщения с `!` (глобальный чат) мост не отправляет — и не пытайся.
- Если мост ответил «remote_disabled»: игрок выключил управление — скажи ему в чате (`/j remote on`), не обходи.
- Деплой стирает код мира игрока: перед деплоем в чужой/рабочий мир скажи пользователю, что будет залито.
