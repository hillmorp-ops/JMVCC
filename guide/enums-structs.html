Перечисления и структуры ​

enum и struct существуют только в компиляторе. В модуль попадает ровно тот код, который ты написал бы руками: член перечисления — обычное число, экземпляр структуры — обычные переменные %player%_hp, round_kills. Ни одного лишнего действия, никаких проверок типов на сервере, никаких словарей. Зато опечатка в члене или поле — ошибка компиляции с подсказкой «Возможно: ...».

enum: фазы и состояния числами ​

jc
enum State { WAITING, COUNTDOWN, RUNNING, OVER }   // 0, 1, 2, 3
enum Slot { SWORD = 0, BOW = 1, FOOD = 8 }         // свои значения; без = — предыдущее + 1

game var state: State = State.WAITING

event<player_join> {
  if (state == State.RUNNING) {
    player::message("&7Раунд идёт, ты зритель")
  }
  player::set_slot_item(item("bread"), Slot.FOOD)  // член — обычное число, годится и в аргумент
}
  • State.RUNNING — числовая константа, ровно как 2. С -O сравнение state == State.RUNNING становится number_in_range (≈1.5 действия против ≈8 у == с текстом), поэтому числа выгоднее текстовых фаз "game".
  • Члены пиши ЗАГЛАВНЫМИ: game, save, if и другие — ключевые слова.
  • State.count — число членов, State.names — список имён по значению (дыры — "?").
  • Неприсвоенная переменная — 0, то есть первый член.

: State у переменной или параметра — только проверки компилятора:

jc
enum Phase { LOBBY, GAME }
enum Mode { SOLO, TEAM }
game var phase: Phase = Phase.LOBBY

function start(p: Phase) { phase = p }

event<player_join> {
  start(Phase.GAME)       // ок
  // start(Mode.TEAM)     — ошибка: член другого enum
  // phase = 7            — ошибка: у Phase нет значения 7
  // phase == "GAME"      — ошибка: сравнение числа с текстом
  phase += 1              // арифметика не проверяется: в рантайме проверок нет
}

Если enum хранится в save var, задай всем членам явные значения (LOBBY = 0, GAME = 1): порядок членов становится частью сохранения, компилятор об этом предупредит.

Имя члена для вывода ​

jc
enum Phase { LOBBY "&eЛобби", GAME "&aИгра", END "&cКонец" }
game var phase: Phase = Phase.LOBBY
game var PHASES = Phase.labels        // список один раз — дальше PHASES[phase] (одно действие)

event<player_join> {
  player::message("Фаза: ${Phase.name(Phase.GAME)}")   // "GAME" — текст прямо в JSON, 0 действий
  player::action_bar(PHASES[phase])                    // подпись по значению
  log("фаза ${phase.name()}")                          // то же, что Phase.name(phase): временный список + l[i]
}

"${phase}" печатает число (компилятор предупредит). Phase.name(x) от переменной строит временный список имён (≈9 действий): если имя нужно часто, сделай game var NAMES = Phase.names один раз.

struct: состояние игрока без префиксов вручную ​

jc
enum Phase { LOBBY, GAME }
struct Profile { coins = 0, best = 0 }                    // сохраняется
struct Run { phase = Phase.LOBBY, hp = 20, kills = 0, owner }

save var %player%: Profile     // поля: save %player%_coins, %player%_best
game var %player%: Run         // поля: game %player%_phase, %player%_hp, ...

event<player_join> {
  %player% ??= Profile()       // новым игрокам — умолчания, старым ничего (проверка по каждому полю)
  %player% = Run(hp = 30)      // сброс полей Run, hp = 30; owner не трогается
  %player%.owner = "%player%"
}

event<player_kill_player> {
  %killer%.kills += 1          // game %killer%_kills — та же семья, что %player%_kills
  %killer%.coins += 5          // save %killer%_coins
  if (%player%.phase == Phase.GAME) {
    player::message("&c-1 жизнь, осталось ${%player%.hp}")
  }
}
  • Экземпляр — обычные переменные <имя>_<поле>: %player%.hp и %player%_hp — одно и то же, старый и новый код можно смешивать.
  • По нику (%player%, %killer%...) и по UUID (%uuid%, %player_uuid%, %killer_uuid%...) — разные переменные: при save var %uuid%: Profile пиши %killer_uuid%.coins, а не %killer%.coins (ошибка struct-key-mismatch с подсказкой). %player% = Profile() у save-экземпляра в player_join стирает прогресс при каждом входе — предупреждение save-reinit, нужен ??=.
  • Объявление не ставит умолчания. game var %player%: Run ничего не делает в JSON — сбрось в player_join (%player% = Run()), а сохраняемое заполни ??=. Если сброса нигде нет — предупреждение.
  • x = Run() ставит каждое поле с умолчанием по порядку, x = Run(hp = 30) меняет одно (только именованные аргументы), x ??= Profile() — только отсутствующие поля, x = y — копия по полям.
  • Поле без умолчания (owner) Run() не трогает. Поле с типом без умолчания — phase: Phase.
  • Умолчания — константы: числа, текст, члены enum, inline var, списки констант, location(...).

Глобальный экземпляр тоже можно:

jc
struct Round { number = 0, alive = [] }
game var round = Round()          // в world_start: round_number = 0, round_alive = []

event<player_join> {
  round.alive.append("%player%")
  player::message("Раунд ${round.number}, живых: ${round.alive.get_list_length()}")
}

Чужой экземпляр по имени ​

Из мирового цикла (там нет %player%) к игроку обращаются по имени — объяви экземпляр в функции или лямбде:

jc
struct Stats { wins = 0 }
save var %player%: Stats

function reward(w) {
  line var who = w
  save var `${who}`: Stats      // та же память, что %player%.wins у этого игрока
  `${who}`.wins += 1
}

event<player_join> { %player% ??= Stats() }

repeat::forever() {
  repeat::for_each_in_list(value::all_players_names) { i, w ->
    reward(w)
  }
  code::wait(1, time_unit = "minutes")
}

Чего нет ​

  • Экземпляр — не значение: нельзя "$x" (пиши "${x.hp}"), x == y, списки структур, Run() вне = и ??=. Для команд и арен — нумерованные экземпляры game var `team${i}`: Team.
  • Структура параметром функции: функция и так работает в потоке вызвавшего события и видит его %player%.hp; для другого игрока передай имя (f("%player%")) или поле.
  • Наследования, методов и вложенных структур нет. Под одним именем можно держать save- и game-структуру (save var %player%: Profile + game var %player%: Run), если имена полей разные; копия x = y такого экземпляра — ошибка (иначе задела бы сохранения).
  • jmvcc decompile enum и struct не восстанавливает: в JSON их нет, он пишет %player%_hp и числа.
