Грабли и проверенные факты ​

Здесь собрано то, чего не видно из сигнатур: как сервер JustMC ведёт себя на самом деле. Почти каждый факт проверен кодом в живом мире (файлы bench/server-check*.jc), полный список с источниками — docs/semantics.md.

Сначала проверьте простое: jmvcc check main.jc -w покажет все ошибки и подозрительные места разом, а jmvcc client logs --errors — ошибки сервера после деплоя.

Код молча не работает ​

Код после какого-то места просто не выполняется ​

Скорее всего, там упала ошибка сервера. Она обрывает остаток строки кода: действия после неё, цикл дальше в этой строке и код вызывающего, если ошибка случилась внутри функции. Другие события работают дальше.

В чате это выглядит как ❌ Ошибка: «Действие <имя> остановило строку кода из-за ошибки: <причина>», по клику — телепорт к блоку в мире кода. Мост выводит это строкой error в jmvcc client logs.

Частые причины:

Что сделалиЧто сказал сервер
m[k] = v / set_map_value на неприсвоенной mждал Словарь, получил Число
l[i], get_list_length, remove_list_value не на спискеждал Список
текст (не числовой) в >=, <, number_in_rangeждал Число, получил Текст
set_text_display_background(hex, 110)ошибка (55 работает, держите ≤ 100)
code::controller_async_run() { ... }«Action should not be executed directly»

Рискованное и непроверенное (компоненты предметов, NBT, угаданные значения) выносите в свой process: скорее всего, упадёт только он (вывод, вживую не проверялось). Подробнее — в Событиях и функциях.

Вся строка события оборвалась после вызова функции ​

В функции стоял break вне цикла. Там он значит «закончить поток» и обрывает всё событие, включая цикл вызывающего. Из функции выходят через return, а цикл вызывающего останавливают code::stop_repeat().

Переменная равна 0, хотя её «нет» ​

Переменная, которой ничего не присваивали, — это число 0 (и 0 в тексте), а не пустой список или словарь. if (x == 0) для неё истинно. Значение по умолчанию задают через ??=: оно присвоится, только если переменной ещё нет.

jc
save var %player%_coins

event<player_join> {
  %player%_coins ??= 100            // новичку 100, старому игроку не трогаем
  player::message("Монет: ${%player%_coins}")
}

save var x = 5 в верхнем коде — сброс на каждом старте

save var со значением на верхнем уровне перезаписывается при каждом запуске мира (компилятор предупреждает). Объявляйте без значения, а значение по умолчанию ставьте через ??=.

Список не растёт ​

append на неприсвоенной переменной ничего не делает и не ругается. Сначала l ??= [] или var l = []. Подробнее — в Списках и словарях.

m.get_map_value(k) без ключа не равен 0 ​

Явные вызовы get_map_value, get_map_value_single, get_list_value без default_value возвращают null. В тексте он выглядит как 0, но == 0 для него ложь. Сахар m[k] и l[i] сам передаёт default_value = 0; в явных вызовах передавайте его вы.

Телепорт в сохранённую точку уносит в 0, 0, 0 ​

Точку ещё не сохраняли, а неприсвоенная переменная — число 0. Держите рядом флаг:

jc
game var %player%_cp
game var %player%_has_cp

event<player_join> {
  if (%player%_has_cp == 1) {
    player::teleport(%player%_cp, keep_rotation = false)
  }
}

event<player_sneak> {
  %player%_cp = value::location
  %player%_has_cp = 1
}

События ​

value::event_block_type == "stone" всегда ложь ​

event_block_type — полное состояние блока: "minecraft:light_weighted_pressure_plate[power=0]". С голым id (и с minecraft:id) оно не совпадёт никогда. Тип блока проверяют так:

jc
event<player_interact> {
  if (value::event_interaction == "physical" && world::event_block_equals([item("stone_pressure_plate")])) {
    player::action_bar("&aСтарт!")
  }
}

value::event_block — это место блока, а не id. Два value::event_block одной плиты через == равны.

Нажимная плита срабатывает много раз ​

Пока игрок стоит на плите, player_interact с "physical" приходит примерно 2 раза в секунду. Добавьте кулдаун или реагируйте только на новую плиту: сравните value::event_block с сохранённым (так сделан паркур в Готовых механиках).

player_move грузит мир ​

Он срабатывает каждый тик, пока игрок движется (20 раз в секунду, и при падении тоже), стоя на месте — ни разу. Сначала дешёвая проверка числа, потом остальное.

ПКМ пустой рукой ничего не делает ​

ПКМ пустой рукой в воздух клиент серверу не шлёт — события нет. С предметом в руке player_right_click приходит один раз на клик.

Клики в меню теряются ​

  • player::show_menu кладёт первый предмет списка в слот 0, дальше по порядку. value::event_slot тоже с 0.
  • В player_click_inventory попадает только верхняя часть (само меню). Клик по своему инвентарю, пока меню открыто, идёт в player_click_own_inventory.
  • Своё меню отличайте по value::open_inventory_custom_id — это custom_id из show_menu.

Кто игрок в player_kill_player ​

Не проверено (нужно два игрока). Не полагайтесь на %player%: пишите %killer% / %victim%, <killer_player> / <victim_player>, value::x<killer_entity>.

А в player_death от урона не от игрока (player::damage) %killer% и %victim% не подставляются — так и остаются текстом.

Сообщение из мирового кода никто не видит ​

world_start (весь код вне событий) идёт до того, как игрок вошёл: log() и сообщения оттуда теряются. Пишите в player_join. При повторном /play даже после старта сообщение может не дойти — помогает code::wait(2, time_unit = "seconds") перед ним.

Потоки и перезапуск ​

После /play всё удвоилось ​

Повторный /play в режиме игры снова запускает player_join, а старый цикл игрока продолжает идти. Нужен токен поколения — рецепт в Событиях и функциях. /build и деплой останавливают все циклы.

Цикл игрока остановился сам ​

Поток, привязанный к игроку, умирает, когда тот выходит, — посреди любого действия. Цикл на весь мир держите в верхнем коде или в code::start_process("имя", target_mode = "NO_TARGET").

В процессе %player% печатается как есть ​

В процессе NO_TARGET игрока нет: %player% и %uuid% остаются текстом, value::uuid = 0. Передайте имя через переменную (local_variables_mode = "COPY").

Данные не сохранились при /build ​

/build убивает процессы сразу. Потом сервер вызывает player_quit для каждого игрока и в том же тике world_stop, где игроков уже нет. world_stop выполняется, но код после code::wait в нём не пойдёт никогда. Сохраняйте игрока в player_quit, мир — в world_stop, без ожиданий. Чтобы не рвать идущий матч, — Мягкая остановка.

Мобы и НПС плодятся с каждым /play ​

Всё, что код поставил или создал (блоки, мобы, стойки, дисплеи), остаётся в мире после /play и /build. А game var с их uuid обнуляются. Верхний код выполняется при каждом старте, так что НПС без проверки будет плодиться. Создавайте один раз (проверено: после повторного /play НПС один):

jc
save var npc
npc ??= ""
if (!world::has_entity([npc])) {
  world::spawn_entity(item("villager_spawn_egg"), location(0, 4, 0, 0, 0), 20, "&aТорговец")
  npc = value::uuid<last_entity>
}

Убрать всех мобов мира: select::all_mobs() + entity::remove(). Дисплеи храните списком uuid в save var и удаляйте на старте.

Блоки из мирового цикла не видны ​

Сервер их ставит, но клиент не видит. Передавайте update_blocks = true в world::set_block — это ещё и в 2.5 раза дешевле на частых изменениях.

С переменными точку собирают так:

jc
event<player_join> {
  var x = 3
  var z = -2
  line var p = variable::set_all_coordinates(x, 4, z, 0, 0)   // всегда задавайте yaw и pitch
  player::teleport(p, keep_rotation = false)
}

Время mm:ss ​

std::mmss(ms) — одно действие на сервере, в 4 раза дешевле самописной функции: 75000 → 01:15. Часы отбрасываются, для них — std::hmmss(ms) → 1:02:05. Принимает миллисекунды.

Текст и цвета ​

  • &a, &c и т. д. работают до конца текста. Hex — &#RRGGBB. MiniMessage (<red>) и §b — нет, видны как текст.
  • Цвет пишите до &l: "&#42A5F5&l1". Код цвета после &l сбрасывает жирность.
  • %% — не экранирование: %%math(...) съедает часть текста. Не пишите %%.
  • %val(health) = 0: такого id нет. Нужен серверный id — %val(current_health). Неизвестный id молча даёт 0.
  • %length(x) для переменной, которой нет, — -1; для текста — длина текста.
  • Перевод строки: \n в тексте или список с merging = "SEPARATE_LINES".
  • Сплошная линия-рамка: &8&m + пробелы. Символы ━ ─ ▬ дают швы.

Как сделать красиво, а не «простынёй в чат», — в Тексте и интерфейсе.

Ещё ловушки ​

  • Две функции с одним именем выполняются обе, по порядку объявления.
  • Условие по нескольким целям истинно, если подходит хоть одна; not if — точное дополнение. Ноль целей: if — нет, not if — да.
  • Аргумент вычисляется один раз: entity::set_custom_name(value::health) по двум выбранным свиньям даст обеим здоровье цели потока (игрока), а не каждой свиньи.
  • Выбранная сущность в NO_TARGET: после select::... действия без <селектора> идут выбранному, читать её значения — value::x<current>. Просто value::x выбранного не видит (0).
  • player::set_spawn_point не поменял value::spawn_location. Возвращайте игрока телепортом в player_respawn после code::wait(1).
  • world::remove_scoreboard несуществующего табло ничего не ломает, строка идёт дальше.
  • Длина строки кода: лимита в 43 блока нет, сервер выполнил строку из 1002 блоков. Компилятор строки не режет.

Не проверено ​

Две вещи пока открыты, нужны два игрока:

  1. Чьё имя подставит %player% в тексте с <all_players> — возможно, каждого получателя. Сохраняйте заранее: line var who = "%player%", потом "$who".
  2. Кто игрок по умолчанию в player_kill_player — убийца или жертва.
