Текст и интерфейс ​

Игру судят глазами, от первого лица. Код может работать идеально, но если игрок видит стену текста в чате, игра выглядит недоделанной. На этой странице разобрано, какой канал вывода для чего годится и как его сделать красивым.

Главное правило: чат — худший канал ​

Агенты и новички любят сыпать в чат всё подряд. Вместо этого:

Что показатьКудаКак
Уведомление: куплено, не хватает, твой ход, рекордaction bar + звукplayer::action_bar + player::play_sound, звук разный для хорошего и плохого
Большое событие: победа, смерть, старт раундаtitleplayer::title(заголовок, подзаголовок, ...)
Прогресс, здоровье босса, таймер раундаboss barplayer::set_boss_bar(id, текст, 0..100)
Таймер и счёт, которые видны всегдаaction bar раз в секундуодин мировой цикл, не каждый тик
Рекорды одной строкойсайдбарworld::create_scoreboard + player::show_scoreboard
Топы и таблоtext display в миретабло над игровой зоной, обновлять только при изменении
Правила при входе, итог раунда одному игрокучат, но блок в рамке3–5 цветных строк между двумя линиями
«X начал игру» для всехтабло или action barне чат

На входе в игру

Хватит 2–3 строк: цель, управление (ЛКМ, ПКМ, предмет), рекорд. Всё остальное игрок узнает из action bar и табло по ходу игры.

Цвета ​

Работают коды &: &a зелёный, &c красный, &e жёлтый, &6 золотой, &7 серый, &8 тёмно-серый, &f белый, &l жирный, &m зачёркнутый. Цвет действует до конца текста или до следующего кода.

Hex-цвета пишутся как &#RRGGBB. Они проверены в названиях предметов, в text display, в чате и в title. В action bar hex не проверяли.

jc
event<player_join> {
  player::message("&aзелёный &cкрасный &7серый &6&lзолотой жирный")
  player::message("&#42A5F5&lСиний жирный &#FFB300янтарный")
  player::give_item(item("stick", "&#ff8800Оранжевая палка", lore = ["&7Ею можно тыкать"]))
}

Сначала цвет, потом &l

Цветовой код после &l сбрасывает жирность. Поэтому пишут "&#42A5F5&l1", а не "&l&#42A5F51".

Что не работает

  • MiniMessage (<red>текст) и §b не работают и выводятся как обычный текст.
  • %% — это не экранирование процента, его не пиши.
  • Эмодзи по памяти могут показаться квадратиками. Значки ⚑ и ☠ на дисплеях проверены, остальные бери в игре из /symbols 1..8.

Подбирай цвет под фон: на светлом полу (white_concrete) нужны насыщенные или тёмные цифры, а серое на сером не читается. В нашем сапёре восьмёрку пришлось затемнить с #9E9E9E до #757575.

Подстановки в тексте ​

  • $x и ${выражение} — значение переменной или выражения: "Монет: ${%player%_coins}".
  • %player%, %killer%, %victim%, %damager% — имена участников события, их подставляет сервер.
  • std::mmss(мс) превращает миллисекунды в мм:сс за одно действие, и его можно писать прямо внутри текста.
jc
save var %player%_coins
game var start = 0

event<player_join> {
  %player%_coins ??= 0
  player::message("&7Привет, &e%player%&7! Монет: &6${%player%_coins}")
  // имя забираем заранее: каким станет %player% в тексте для <all_players>, не проверено
  line var who = "%player%"
  player::action_bar<all_players>("&e$who &7в игре")
  player::action_bar("&7В игре уже ${std::mmss(value::timestamp - start)}")
}

Имя игрока для всех

Каким станет %player% в тексте, отправленном через <all_players>, — открытый вопрос: возможно, у каждого получателя своим. Сначала сохрани имя: line var who = "%player%", а потом пиши "$who ...".

Как устроены подстановки и выражения, читай в разделе Синтаксис, а про %player%_x в именах переменных — в разделе Переменные.

Сообщение в чат — блоком в рамке ​

Если игроку правда нужна пачка информации (правила при входе, итог раунда), оформи её как интерфейс, а не как реплику в чате. Сверху и снизу ставь линию из &8&m и примерно 50 пробелов: зачёркнутые пробелы дают сплошную черту. Символы ━ ─ ▬ оставляют швы. Каждую строку окрашивай, заголовок делай в &#RRGGBB&l, отступ — два пробела.

jc
inline var LINE = "&8&m                                                  "

event<player_join> {
  player::message([
    LINE,
    "  &#FFB300&lЗМЕЙКА",
    "  &7Ешь &6яблоки&7, не врежься в бортик",
    "  &e1-4 &7— повороты, &aизумруд &7— старт",
    LINE
  ], merging = "SEPARATE_LINES")
}

Строки разделяет merging = "SEPARATE_LINES", и \n внутри текста тоже переносит строку.

log(...) — не для игроков

log("x = $x") — отладочный вывод для тебя и агента: мост пишет его в jmvcc client logs. Но в чате его видят все игроки, поэтому убирай log из готовой игры. Подробнее — в разделе Мод JMVCC Bridge.

Подсказка при наведении и копирование по клику ​

Текстовые компоненты с наведением (show_text) и копированием по клику (copy_to_clipboard) проверены на сервере.

jc
event<player_join> {
  var rules = variable::set_component_hover("&e[Правила]", "&7Ешь яблоки, не врезайся в стены")
  player::message(rules)
  var seed = variable::set_component_click("&b[Скопировать код]", "ABC-123", "COPY_TO_CLIPBOARD")
  player::message(seed)
}

Остальные действия с компонентами (variable::set_component_*, append_component и другие) смотри в справочнике variable.

Action bar: уведомления и HUD ​

Action bar — строка над хотбаром. Подходит для всего короткого: «куплено», «не хватает», «перезарядка», таймер.

Уведомление всегда идёт со звуком, и звук разный для разных исходов:

jc
save var %player%_coins

function buy(goods, price) {
  if (%player%_coins < price) {
    player::action_bar("&cНе хватает монет: &f${%player%_coins}&7/&f$price")
    player::play_sound(sound("entity.villager.no"))
    return
  }
  %player%_coins -= price
  player::give_item(goods, 1)
  player::action_bar("&aКуплено! &7Осталось &e${%player%_coins}")
  player::play_sound(sound("entity.experience_orb.pickup", 0.3, 1.8))
}

event<player_right_click> {
  if (value::event_equipment_slot != "hand") { return }
  buy(item("bread"), 5)
}

Action bar гаснет через несколько секунд. Для постоянного HUD его нужно обновлять раз в секунду из одного мирового цикла, а не каждый тик и не отдельным циклом на каждого игрока. Подсказки тоже идут в action bar, поэтому после подсказки HUD стоит придержать на ~2 секунды, иначе он её сразу перебьёт. Так сделано в нашем сапёре:

jc
game var start = 0
game var hint_until = 0     // до этого момента HUD не перебивает подсказку

function hint(txt) {
  hint_until = value::timestamp + 2000
  player::action_bar(txt)
  player::play_sound(sound("block.note_block.pling"))
}

event<player_join> {
  hint("&7Открой клетку &eЛКМ")
}

// верхний код = мировой цикл без цели; только простая установка переменных до него
start = value::timestamp
repeat::forever() {
  if (value::timestamp >= hint_until) {
    player::action_bar<all_players>("&e${std::mmss(value::timestamp - start)} &7| &fИгроков: ${value::players}")
  }
  code::wait(1, time_unit = "seconds")
}

Почему цикл стоит в верхнем коде и почему перед ним ничего рискованного, объяснено в разделе События, функции, процессы.

Title: большие моменты ​

player::title(заголовок, подзаголовок, fade_in, stay, fade_out), время — в тиках (20 = 1 с). Title нужен для победы, смерти, старта раунда и отсчёта, а не для каждой мелочи.

jc
event<player_death> {
  player::title("&c&lТЫ ВЫБЫЛ", "&7Жди следующий раунд", 10, 40, 10)
  player::play_sound(sound("entity.generic.explode", 0.5, 1))
}

function countdown() {
  repeat::on_range(0, 4) { i ->       // on_range включает конец: 0..4 — это 5 шагов
    player::title<all_players>("&e${5 - i}", "&7Раунд начинается", 0, 25, 0)
    player::play_sound<all_players>(sound("block.note_block.hat"))
    code::wait(1, time_unit = "seconds")
  }
  player::title<all_players>("&a&lВПЕРЁД!", "", 0, 30, 10)
}

Boss bar: прогресс ​

Полоса сверху экрана. Прогресс задаётся от 0 до 100: 50 — половина, а 0.5 — почти пустая полоса. Цвета & в названии работают (&4&l — тёмно-красный жирный). id — твоё имя полосы: по нему её обновляют и убирают.

jc
inline var BAR = "goal"
inline var GOAL = 20
game var done = 0

function show_progress() {
  player::set_boss_bar<all_players>(BAR, "&6&lСобрано &f$done&7/&f$GOAL", done / GOAL * 100, color = "YELLOW", style = "NOTCHED_10")
}

event<player_break_block> {
  done += 1
  show_progress()
  if (done >= GOAL) {
    player::remove_boss_bar<all_players>(BAR)
    player::title<all_players>("&a&lГОТОВО", "&7Цель выполнена", 10, 40, 10)
    player::play_sound<all_players>(sound("ui.toast.challenge_complete"))
  }
}

Полоса здоровья босса и компас в boss bar разобраны в разделе Готовые механики.

Звуки ​

Каждому исходу нужен свой звук. Частые звуки делай тише и выше, например sound("entity.experience_orb.pickup", 0.3, 1.8): второй аргумент — громкость, третий — высота. Без location звук слышит сам игрок, не из какой-то точки.

ИсходЗвук из наших игр
Клик, нажатиеblock.wooden_button.click_on, block.stone_button.click_on
Успех, покупкаentity.experience_orb.pickup
Отказ, «нельзя»entity.villager.no
Новый уровень, рекордentity.player.levelup
Подсказка, тик отсчётаblock.note_block.pling, block.note_block.hat
Проигрышentity.generic.explode
Победаui.toast.challenge_complete

Другие звуки ищи командой jmvcc search (например, jmvcc search sound bell). Компилятор проверяет имена звуков и подсказывает похожие.

Сайдбар: рекорды справа ​

Таблица справа от экрана. В set_scoreboard_score текст — это подпись строки, число — её счёт, &-цвета работают.

jc
save var best
save var best_name

best ??= 0
best_name ??= "никто"
world::create_scoreboard("rec", "&6&lРЕКОРД")
world::set_scoreboard_score("rec", "&e$best_name", best)

event<player_join> {
  player::show_scoreboard("rec")
}

Чтобы заменить строку, убери старую (world::remove_scoreboard_score_by_name) и поставь новую. Удаление несуществующего табло (world::remove_scoreboard) ничего не ломает.

Табло в мире: text display ​

Топы и счёт игры лучше всего смотрятся на табло из text display над игровой зоной: с тёмным полупрозрачным фоном, повёрнутое к игроку и обновляемое только тогда, когда данные изменились.

jc
save var board_u          // uuid табло: сущности переживают /play, переменные game — нет
game var top_txt = "&8—"

function board_style() {
  entity::set_display_billboard<last_entity>("VERTICAL")         // поворачивается к игроку
  entity::set_text_display_background<last_entity>("#000000", 55) // прозрачность не больше 100
  entity::set_text_display_text_shadow<last_entity>(true)
}

// изменился топ → один раз переписать текст (не каждый тик!)
process upd_board() {
  select::entity_by_name([board_u])
  entity::set_text_display_text(["&#FFB300&lТОП-5", top_txt], merging_mode = "SEPARATE_LINES")
  select::reset()
}

// мировой код: поставить табло, только если его ещё нет
board_u ??= ""
if (!world::has_entity([board_u])) {
  world::spawn_text_display(location(0.5, 6, -10.5, 0, 0), "top", merging_mode = "SEPARATE_LINES", displayed_text = ["&#FFB300&lТОП-5", top_txt])
  board_u = value::uuid<last_entity>
  entity::set_display_scale<last_entity>(vector(1.5, 1.5, 1.5), "SET")
  board_style()
}

Что важно:

  • Дисплеи, как и мобы, переживают /play и /build. Храни uuid в save var и ставь дисплей, только если его нет. Иначе каждый старт мира добавит ещё одну копию, и компилятор об этом предупредит.
  • Фон set_text_display_background(hex, 110) вызвал ошибку и оборвал строку кода, а 55 работает. Держи значение не больше 100.
  • Смена текста дорогая: ≈12 мкс за строку, ≈31 за три цветные строки (дороже только set_display_transformation_matrix, ≈34; поворот и телепорт ≈4–6). Поэтому текст меняют, только когда значение изменилось, и не держат дисплеев с текстом, который переписывается каждый тик.
  • Перенос \n проверен в сообщениях и в display_hologram. Для отдельных строк в дисплее надёжнее передавать список с merging_mode = "SEPARATE_LINES", как сделано выше.

Как собрать текст топа из словаря, показано в разделе Готовые механики → Топ на табло.

Текст прямо на блоке ​

Информацию лучше показывать на самом объекте: цифры, лежащие на верхушке блоков, а не легенду «какой блок что значит» сбоку. Дисплей с yaw 0 и pitch -90 ложится плашмя и читается ровно, если стоять с юга, лицом на север. Текст привязан к нижнему краю строки, поэтому сдвигай z на +0.125·S, где S — масштаб (при 4.5 цифра почти заполняет клетку).

jc
save var marks
marks ??= []      // неприсвоенный список молча глотает append

function mark(x, top, z, txt) {
  line var loc = variable::set_all_coordinates(x + 0.5, top + 0.01, z + 0.5 + 0.125 * 4.5, 0, -90)
  world::spawn_text_display(loc, "mark", displayed_text = [txt])
  marks.append(value::uuid<last_entity>)                 // uuid сохраняем ПЕРВЫМ
  entity::set_display_scale<last_entity>(vector(4.5, 4.5, 4.5), "SET")
  entity::set_text_display_background<last_entity>("#000000", 0)    // прозрачный фон
}

event<player_join> {
  mark(0, 4, 0, "&#42A5F5&l1")
}

top равен 4.0 на полном блоке, верхняя грань которого на y=4, и на 0.5 больше на нижнем полублоке. location(...) принимает только числа-константы, поэтому с переменными используют variable::set_all_coordinates.

Голограмма одному игроку ​

player::display_hologram(место, текст) показывает текст этому игроку. Перенос \n и цвета работают. Вторая голограмма в той же точке заменяет первую, так что табло можно обновлять, показывая его заново в том же месте.

jc
event<player_join> {
  player::display_hologram(location(0.5, 66, 0.5, 0, 0), "&6&lМАГАЗИН\n&7ПКМ компасом")
}

Меню вместо команд ​

Большие списки (топ на 50 игроков, магазин, выбор режима) удобно показывать в меню сундука через player::show_menu. Первый предмет списка попадает в слот 0, custom_id отличает твоё меню от чужих, а &-коды в названии и описании item(...) превращаются в цветной текст. Полный магазин с разбором кликов есть в разделе Готовые механики.

Головы игроков и особые предметы

Не выдумывай base64 для голов. Попроси игрока набрать нужные головы (например, из /hdb) в инвентарь, выполни jmvcc client items и вставь готовые строки inline var ITEM_… = item_raw("…"). Подробнее — в разделах Мод JMVCC Bridge и Декомпилятор.

Красиво — не значит тяжело ​

  • Частицы и звуки запускай только по событию (клик, удар), а не в цикле каждый тик.
  • Отклик показывай там, куда смотрит игрок: частицы на грани блока, по которой кликнули, а не в фиксированной точке над объектом, где их сверху не видно. Рецепт есть в разделе Готовые механики.
  • HUD обновляй раз в секунду одним мировым циклом.
  • Дисплеи создавай, только когда меняется состояние, а большие пачки растягивай на несколько тиков.

Сколько стоит каждое действие, разобрано в разделе Оптимизатор.

Чек-лист перед «готово» ​

  • В чат уходят только правила при входе (2–3 строки или блок в рамке) и итог. Всё остальное идёт в action bar, title, boss bar или на табло.
  • У каждого исхода свой звук, хорошее и плохое звучат по-разному.
  • Цвет стоит перед &l, цифры читаются на своём фоне.
  • Табло и метки обновляются только при изменении, а их uuid лежат в save var.
  • log(...) убраны.
  • Игра проверена глазами: jmvcc client deploy, затем jmvcc client shot, на скриншоте всё в кадре и читается.
