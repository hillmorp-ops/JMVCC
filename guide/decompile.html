Декомпилятор ​

jmvcc decompile превращает модуль JSON обратно в JustCode. Модуль может быть выгрузкой из игры или результатом jmvcc compile (с -O и без). Получается .jc, который компилируется в тот же JSON, и команда сразу это проверяет.

Зачем это нужно:

  • старый модуль, собранный руками в игре, — переписать в коде и дальше править текстом;
  • чужой модуль — разобраться, как он устроен;
  • агенту — прочитать, что сейчас залито в мир.

Команды ​

text
jmvcc decompile export.json              # → export.jc рядом (или export.decompiled.jc) + проверка круга
jmvcc decompile export.json -o main.jc   # предметы уйдут в main.items.jc, main.jc его импортирует
jmvcc decompile "https://…/handlers/<id>?token=…" -o main.jc   # модуль по ссылке
jmvcc decompile export.json --no-verify  # без сравнения (компиляция результата всё равно проверяется)
jmvcc decompile export.json --allow-diff # код выхода 0 даже при различиях
jmvcc decompile export.json -o main.jc --force   # перезаписать .jc, написанный не decompile

Ссылку на модуль даёт команда /module в игре. Она одноразовая: ответ 401 / 403 / 404 от api.creative.justmc.io почти всегда значит, что ссылка истекла. Возьми новую.

Проверка круга ​

После записи .jc команда компилирует его и сравнивает с исходным JSON:

text
 Успех  main.jc: 250 строк, 14 обработчиков, 153 действий
Круг: compile даёт тот же JSON (после нормализации, docs/decompile.md)
Код выходаЗначит
0круг без различий: ничего не потеряно
2есть различия — эти данные при заливке потеряются (--allow-diff → 0)
1ошибка: не прочитать, не JSON, результат не компилируется, файл не перезаписан

Различия печатаются списком. Перед тем как заливать переписанный модуль, разберись с каждым.

«Тот же JSON» — после нормализации. Не считаются различием, например, порядок обработчиков и аргументов, пустой слот против отсутствующего аргумента, minecraft: в id звука, номера временных переменных jmcc.N. Полный список — в docs/decompile.md.

Пустые перечисления

Пустое перечисление в выгрузке декомпилятор заменяет первым значением (для boolean — умолчанием сервера). Для boolean так и считает сервер, для остальных перечислений это допущение, на сервере не проверено. CLI печатает, каким аргументам что подставлено.

Твой код не перезапишется ​

Файл .jc, написанный не декомпилятором, не перезаписывается никогда. Декомпилятор узнаёт свой файл по шапке // Декомпилировано: jmvcc decompile.

  • Без -o в таком случае пишется <имя>.decompiled.jc.
  • С -o — ошибка. Нужен другой путь или --force.

Поэтому цикл compile main.jc → decompile main.json исходник не тронет.

Как выглядит результат ​

  • Действия — с именованными аргументами: player::message(messages = ["a"]). Перечисление, равное умолчанию компилятора, не пишется. Имена — JMVCC, как в справочнике: player::give_item, variable::sort(list = l), variable::length(map = m) (ветку списка или словаря компилятор берёт по имени аргумента).
  • Условия — if / else if / else, is_inverted → !, сравнения с одним значением → a == b, a < b.
  • Циклы — переменные цикла явными аргументами: repeat::on_range(variable = i, start = 0, end = 3) { }, внутри break / continue.
  • x = v, x += n, out = obj::f(...), индексы l[i] и m["k"] — там, где компилятор выберет то же действие.
  • Свои функции и процессы — name(); процесс с нестандартными режимами — code::start_process(...).
  • Переменные объявлены группами: game var / save var в начале файла, var / line var в начале обработчика. Необычные имена — в обратных кавычках: process `#DNBS#DONOTTOUCH#PLAY`().
  • Текст: %var_local(x) → ${x}. %math(...) в числе — выражением (speed * 7), если компилятор соберёт ту же строку.
  • Временные jmcc.N компилятора становятся jmcc_tN.
  • Что выражено не один в один, помечено комментарием // decompile: ....

Предметы из игры (бинарный NBT, base64 на тысячи символов) уходят константами в <имя>.items.jc:

text
inline var ITEM_КИЙ = item_raw("H4sI…")  // stick "Кий"

Основной файл начинается с import "<имя>.items.jc", так что main.jc можно читать целиком и грепать, не утопая в base64. Имя константы берётся из названия предмета, без названия — из id (ITEM_PLAYER_HEAD), одинаковые имена получают _2, _3.

Фабрики *_raw ​

Для того, что обычным литералом не записать, есть фабрики, которые пишут ровно этот JSON:

jc
inline var ITEM_STONE = item_raw("{\"id\":\"minecraft:stone\",\"count\":1}")

event<player_join> {
  player::message(text_raw("<red>Привет", parsing = "minimessage"))
  player::give_item(ITEM_STONE)
  var_raw("joins", "game") = 1
  code::wait(number_raw("%math(2+1)"))
  player::play_sound(sound("block.note_block.harp", 1, 2, variation = "", source = "RECORD"))
}
ФабрикаЧто даёт
item_raw("H4sI…")предмет как его хранит сервер (base64 gzip NBT) или JSON-строка {"id": ...}
text_raw("…", parsing = "plain")текст с режимом разбора: legacy, plain, minimessage, json
number_raw("%math(…)")число, которое сервер хранит текстом-плейсхолдером
var_raw("x", "game")переменная с явной областью, без объявления
enum_raw("RECORD")значение перечисления без проверки
sound(id, …, variation, source)звук с полями variation и source
function_info(description, icon, hidden)описание, иконка и скрытость функции из игры, первой строкой тела

Аргумент действия, которого нет в справочнике (старый блок из игры), принимает значение *_raw как есть: source = enum_raw("RECORD"). Обычное значение в таком аргументе — ошибка «Неизвестный аргумент», так что опечатки ловятся как раньше.

Как переделать старый модуль ​

  1. В игре: /module → ссылка на модуль.
  2. jmvcc decompile "<ссылка>" -o main.jc — проверь, что круг без различий (exit 0).
  3. Правь main.jc. Константы предметов не трогай, они в main.items.jc.
  4. jmvcc check main.jc, потом jmvcc client deploy main.jc (см. мод и CLI).

Хвосты jmcc.fN

Старые версии компилятора резали длинные строки на функции jmcc.fN. Декомпилятор вставляет такой хвост обратно на место единственного вызова. Хвост с return вставляется, только если вызов последний в функции, иначе остаётся функцией jmcc_fN.

Ограничения ​

  • Аргумент вне справочника со значением, у которого нет формы *_raw (место, вектор, звук, список), пропускается с заметкой. Круг покажет различие.
  • Словарь-литерал с данными, пустой слот внутри списка, значение неизвестного типа — комментарий и различие.
  • else без условия перед ним и условие без тела выписаны закомментированными, это различие.
  • Параметры функций из игры (parameters) не пишутся — различие.
  • Имя функции, которое JustCode не объявит (item, floor, $ в имени), становится fn_item, fn_a_b. В JSON имя станет другим, и вызовы из игры по старому имени его не найдут. Круг это покажет.
