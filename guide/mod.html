Мод JMVCC Bridge ​

JMVCC Bridge — клиентский мод Fabric. Он открывает мост между игрой и командой jmvcc client: агент (или ты сам из терминала) заливает модуль в мир, запускает его и читает ошибки сервера, не трогая клавиатуру. Игрок в любой момент отключает это командой /j remote off.

Что умеет ​

  • Деплой одной командой. jmvcc client deploy game.jc компилирует файл, загружает его и делает в игре /build → /dev → /module loadUrl force … → /play. Потом печатает ошибки, log(...) и сообщения модуля.
  • Журнал сервера. Мод разбирает чат на ошибки кода, предупреждения, log(...), системные сообщения и чат игроков и пишет его по сессиям. Ошибка приходит вместе с координатами блока кода.
  • Переменные мира. jmvcc client vars game|save показывает значения всех переменных, обходя страницы /env var list.
  • Руки в игре. Клавиши, клики по слотам меню, правый клик предметом, кнопки экранов (например, «Возродиться»), скриншоты.
  • Предметы из инвентаря. jmvcc client items превращает головы /hdb и предметы с NBT в готовые строки inline var ITEM_… = item_raw("…").
  • Мягкая остановка. /j build и deploy --graceful дают коду доиграть сессии перед /build, подробнее в разделе Мягкая остановка.

Установка ​

Нужны Minecraft 26.2, Fabric Loader 0.20.1+, Fabric API 0.161.0+26.2 и Java 25. Мод только клиентский: на сервер ставить ничего не надо.

Готового jar в релизах пока нет, мод собирается из исходников в client-mod/ (нужен JDK 25):

bash
cd client-mod
JAVA_HOME=D:/minecraft/java25 ./gradlew build
powershell
cd client-mod
$env:JAVA_HOME='D:\minecraft\java25'; .\gradlew.bat build

Путь к JDK — свой. Готовый файл: client-mod/build/libs/jmvcc_bridge-0.1.0.jar. Положи его в <папка игры>/mods рядом с Fabric API и перезапусти игру.

При старте мод:

  • поднимает HTTP-сервер на 127.0.0.1:47321 (если порт занят, пробует следующие 10);
  • пишет ~/.jmvcc/bridge.json с портом и токеном (на Windows %USERPROFILE%\.jmvcc\bridge.json), CLI читает его сам; при выходе из игры файл удаляется;
  • хранит настройки в <папка игры>/config/jmvcc-bridge.json (remote, port, token);
  • пишет журнал в ~/.jmvcc/logs/<id>.jsonl.

Проверка: зайди в свой мир на сервере и выполни в терминале

bash
jmvcc client status

Если видишь игрока, сервер и управление: включено, мост работает. Установку самого jmvcc смотри в разделе Установка и первый мир.

Команды в игре ​

/j и /jmvcc — одно и то же. Это клиентские команды: на сервер они не уходят.

КомандаЧто делает
/j remote offзапретить агенту управлять клиентом: команды, деплой, клики, клавиши
/j remote onразрешить снова. Состояние сохраняется в конфиг
/j statusуправление вкл/выкл, порт, текущая сессия, сколько ошибок, идёт ли остановка
/j logsпапка логов (клик откроет) и последние 5 ошибок с кнопкой «к блоку»
/j token resetновый токен, старые клиенты получат 401 (jmvcc client перечитает токен сам)
/j build [сек]мягко остановить мир: код доигрывает сессии (по умолчанию до 90 с, можно 1..600), потом мод шлёт /build
/j build cancelотменить остановку, в том числе начатую агентом
/j build forceне ждать, /build сразу
/j build statusспросить код мира: идёт ли остановка и сколько сессий в работе

/j build без мягкой остановки в коде

Если код мира не ответил за 3 секунды, мягкой остановки в нём нет. Тогда мод сам /build не шлёт: он подставляет команду в чат, и ты подтверждаешь её Enter. Как добавить остановку в свою игру, написано в разделе Мягкая остановка.

Безопасность ​

  • Только твой компьютер. HTTP слушает лишь 127.0.0.1, и каждый запрос идёт с токеном Authorization: Bearer …. Без токена мост отвечает 401.
  • Выключатель у игрока. После /j remote off всё, что меняет игру (команды, деплой, клики, клавиши, кнопки, остановка), получает ошибку remote_disabled. Агент должен сказать тебе об этом, а не обходить запрет. Чтение журнала, скриншоты и список предметов работают и при выключенном управлении, /env var list — нет.
  • Агента видно. Перед действием мод показывает title «🤖 Агент работает» и ждёт секунду. Пока агент управляет, в углу экрана висит плашка «🤖 JMVCC: управляет агент», и твой ввод в игру не идёт. Когда агент закончил, на 2 с появляется «✔ JMVCC: агент закончил». Если агент только читает, плашка спокойная: «🔎 JMVCC: агент получает информацию».
  • Чат и выход под замком. Сообщения с ! (глобальный чат) мост не отправляет. Кнопки «Главное меню», «Отключиться», «Выйти» он не нажимает.
  • /j remote off работает всегда. Между операциями клавиши чата и / остаются твоими, так что выключить агента можно даже посреди длинной серии.

Деплой стирает код мира

client deploy заливает модуль с force: весь код мира заменяется. Не направляй агента в чужой или рабочий мир, не договорившись, что именно будет залито.

Журнал и log(...) ​

Мод пишет журнал по сессиям. Новая сессия начинается на сообщении «Мир запущен в режиме игры» и при входе на сервер. Каждое событие получает тип:

ТипЧто это
error, warning, criticalошибки и предупреждения кода; у ошибки есть block — координаты блока
code_noticeошибка кода в непривычном формате (есть ссылка на блок, но тип не распознан); --errors и deploy её показывают
logстроки из log(...) в твоём коде
systemсообщения сервера: загрузка модуля, запуск мира
chat, broadcastчат игроков и объявления сервера; по умолчанию не показываются
sessionслужебные отметки: начало сессии, вход и выход из игры

log(...) — отладочная печать для агента. Части склеиваются через пробел, $x и %player% работают как в player::message:

jc
game var round = 0

event<player_join> {
  log("вошёл %player%, раунд $round")
}

Строка попадёт в jmvcc client logs с типом log. Её видят в чате все игроки, поэтому, когда код заработает, log лучше убрать.

CLI jmvcc client ​

Самое ходовое (весь список с опциями — в разделе Команды CLI):

bash
jmvcc client status                    # мост, игрок, сервер, управление, сессия
jmvcc client deploy game.jc            # compile → загрузка → /build, /dev, /module loadUrl, /play → ошибки
jmvcc client deploy game.jc --graceful # то же, но сначала код доигрывает сессии
jmvcc client logs --errors             # ошибки текущей сессии
jmvcc client logs --since 42           # только новое (последний seq печатается внизу)
jmvcc client send "/play"              # команда серверу или сообщение в чат (не с !)
jmvcc client vars game coins           # переменные мира со значениями
jmvcc client items                     # предметы рюкзака → строки item_raw("…")
jmvcc client control begin             # серия действий под одним предупреждением игроку
jmvcc client key forward sprint --ms 2000
jmvcc client screen | click 3 | use | close | button Возродиться | shot

Коды выхода:

КодЗначит
0всё хорошо
1деплой не удался или в логах есть error / critical
2мост недоступен: игра не запущена, нет мода или bridge.json устарел
3игрок выключил управление (/j remote off) — попроси его набрать /j remote on

Git Bash и команды со слешем

Git Bash превращает /build в путь Windows. CLI обычно это чинит сам, но надёжнее писать "//build" или задать MSYS_NO_PATHCONV=1.

HTTP API кратко ​

CLI — тонкая обёртка над HTTP. Свой инструмент можно подключить напрямую: прочитай порт и токен из bridge.json и отправь запрос.

bash
curl -H "Authorization: Bearer <token>" http://127.0.0.1:47321/status
ЗапросЧто делает
GET /statusподключён ли игрок, сервер, управление, сессия, идёт ли остановка (drain)
GET /sessionsсписок сессий журнала
GET /logs?session=…&types=…&since=…события сессии
GET /screenоткрытое окно, слоты и кнопки
GET /inventoryпредметы инвентаря и окна со строкой raw для item_raw
POST /commandкоманда серверу или сообщение в чат
POST /deployцепочка /build → /dev → /module loadUrl → /play; graceful: true — с мягкой остановкой
POST /stopтолько мягкая остановка и /build, без заливки
POST /customclickпакет custom click: в коде мира сработает event<player_custom_click>
POST /click, /use, /close, /button, /keyклик по слоту, правый клик, закрыть окно, кнопка экрана, клавиши
POST /controlначать или закончить серию действий
POST /screenshotскриншот в ~/.jmvcc/screenshots/

Ошибка приходит как HTTP 4xx/5xx и { "error": "<код>", "message": "<по-русски>" }. Самые частые: 403 remote_disabled, 409 not_connected (игрок не на сервере), 409 busy (идёт другая операция).

Полный контракт с телами запросов и ответов — docs/bridge-api.md.
