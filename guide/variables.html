Переменные ​

Переменная объявляется словом var, а слово перед ним задаёт её область видимости и срок жизни. Неправильно выбранная область — частая причина багов «монеты обнулились» и «в другом событии пусто», так что начни с таблицы.

Пять видов ​

ОбъявлениеГде виднаСколько живётДля чего
var xв текущем потоке и во всех вызванных функцияхпока не закончится запуск событияобщие данные события и его функций
line var xтолько в своей строке кода (тело события или функции)до конца этой строки, переживает code::waitчерновые значения внутри функции
game var xво всём коде мирадо перезапуска мирасостояние игры: раунд, списки игроков
save var xво всём коде мирапереживает перезапускмонеты, рекорды, прогресс
inline var Xна этапе компиляции—константы: подставляются в код
jc
game var round = 0                   // общий счётчик раундов, сброс при перезапуске мира
save var %player%_coins              // свои монеты у каждого игрока, сохраняются
inline var PRICE = 5                 // константа: в коде везде будет 5

event<player_join> {
  %player%_coins ??= 100
  var greeting = "Привет, %player%"  // локальная: живёт только в этом запуске события
  line var hint = "&7Монет: ${%player%_coins}, цена: $PRICE"
  player::message(greeting)
  player::message(hint)
}

var и функции: общие переменные ​

Функция видит var вызвавшего её кода и может их менять. Параметры функции — тоже общие переменные. Это удобно, но легко устроить сюрприз:

jc
function add_bonus() {
  var total            // объявление без значения: «total задают снаружи»
  total += 10          // меняет total того, кто вызвал
}

event<player_join> {
  var total = 5
  add_bonus()
  player::message("Итого: $total")   // 15
}

Для черновых значений внутри функции бери line var. Такая переменная в чужие строки не уходит и ничего не затрёт у вызывающего:

jc
function price_with_tax(price) {
  line var tax = price * 0.2          // черновик: виден только в этой функции
  return price + tax
}

event<player_join> {
  var tax = 100                       // своя tax вызывающего не пострадает
  var p = price_with_tax(50)
  player::message("Цена $p, tax всё ещё $tax")
}

line var переживает ожидание

line var живёт до конца своей строки кода, в том числе после code::wait(...) в этой строке. Цена у неё та же, что у var и game var.

Что ещё стоит знать о потоках: событие игрока обрывается на ходу, когда игрок выходит. Ошибка сервера останавливает остаток строки кода. Подробности на странице События, функции, процессы.

Переменная без значения — это число 0 ​

Если переменной ни разу ничего не присвоили, она равна числу 0, а в тексте выводится как 0. Это не пустой список, не пустой словарь и не локация. Отсюда три правила.

1. Значение по умолчанию задаётся через ??=. Присваивание сработает, только если переменной ещё не существует:

jc
save var %player%_coins
save var %player%_level

event<player_join> {
  %player%_coins ??= 100     // новому игроку 100, у старого останется его значение
  %player%_level ??= 1
  player::message("Монет: ${%player%_coins}, уровень ${%player%_level}")
}

??= проверяет, существует ли переменная, а не равна ли она нулю. После x = 0 выражение x ??= 5 уже ничего не сделает. x ??= f() вызывает f только тогда, когда x ещё нет.

2. Список и словарь сначала создают. Добавление в несозданный список молча ничего не делает, а запись в несозданный словарь — ошибка сервера, которая обрывает строку:

jc
save var top_scores
game var queue

event<player_join> {
  top_scores ??= variable::create_map_from_values([], [])
  queue ??= []
  top_scores["%player%"] = 0
  queue.append("%player%")
}

3. Перед телепортом на сохранённую точку проверяй флаг. Несохранённая локация — это 0, а не точка:

jc
game var %player%_cp
game var %player%_has_cp

event<player_interact> {
  if (value::event_interaction == "physical") {
    %player%_cp = value::location
    %player%_has_cp = 1
  }
}

event<player_move> {
  if (value::y_coord < 0 && %player%_has_cp == 1) {
    player::teleport(%player%_cp, keep_rotation = false)
  }
}

Где объявлять ​

  • game var и save var видны во всём файле, порядок объявления не важен. Повторять объявление без значения можно, например в нужном событии для наглядности.
  • var x без значения объявляет имя и не создаёт ни одного блока. Так помечают переменную, которую задают в другом месте.
  • game var x = 0 вне событий выполняется при запуске мира. Для game var это нормально: она и так сбрасывается при перезапуске.

Две ловушки на верхнем уровне

text
save var best = 0   // предупреждение: перезаписывается при КАЖДОМ запуске мира, рекорд пропадёт
var speed = 2       // предупреждение: это переменная world_start, в событиях она будет пустой

Правильно так: save var best плюс best ??= 0 в событии. Общую переменную объявляй как game var speed = 2.

Несколько сразу ​

Через запятую можно объявить несколько переменных, это то же самое, что несколько строк:

jc
game var state = 0, alive, round_start = 0
save var %player%_wins, %player%_losses

event<player_join> {
  var a, b = 0, c
  line var i = 0, n = 10
  %player%_wins ??= 0
  %player%_losses ??= 0
  player::message("a=$a b=$b c=$c, $i из $n, побед ${%player%_wins}")
}

Имена с игроком: %player%_x ​

Плейсхолдер в имени делает переменную своей для каждого игрока. На сервере имя превращается в Steve_coins, Alex_coins и так далее:

jc
save var %player%_kills
save var %killer%_kills

event<player_kill_player> {
  %killer%_kills += 1                    // то же хранилище, что %player%_kills у убийцы
  player::message<killer_player>("&aУбийств: ${%killer%_kills}")
}

event<player_join> {
  %player%_kills ??= 0
}

%killer%_kills и %player%_kills для одного и того же игрока — одна переменная, ведь имя подставляется во время игры.

Имена в обратных кавычках ​

В обратных кавычках имя может содержать пробелы, любые символы и подстановки $x или ${...}:

jc
save var `лучшее время`
inline var MODE = "duel"

event<player_join> {
  `лучшее время` ??= 0
  var i = 2
  var `ячейка ${i}` = 1          // имя на сервере: "ячейка %var_local(i)" → "ячейка 2"
  game var `режим $MODE` = 1     // inline подставляется при компиляции: "режим duel"
  player::message("Рекорд: ${`лучшее время`}")
}

Если имя с подстановкой или плейсхолдером используется вне своего объявления, его тоже нужно объявить, и слово перед var задаёт область. Без объявления будет ошибка unknown-identifier. Пример: +1 победа игроку, имя которого лежит в списке. Так бывает в цикле мира, где цели-игрока нет:

jc
game var alive

event<player_join> {
  alive ??= []
  alive.append("%player%")
}

process finish_round() {
  line var w = alive[0]
  save var `${w}_wins`
  `${w}_wins` += 1                 // на сервере это Steve_wins, то же, что %player%_wins у Steve
  player::message<all_players>("&6Победил $w")
}

Константы inline var ​

inline var вычисляется при компиляции и подставляется в каждое место, где встречается. Блоков она не создаёт. Значение должно быть известно заранее: число, текст, результат фабрики. Результат действия не подойдёт. Объявлять её без значения нельзя.

jc
inline var MAX_HP = 200
inline var TITLE = "&4&lКороль"
inline var HALF = MAX_HP / 2

event<player_join> {
  player::give_item(item("nether_star", TITLE), 1)   // константа годится как литерал фабрики
  player::message("$TITLE: $MAX_HP HP, половина — $HALF")
}

Только inline var можно передавать в фабрики item(), location() и другие. Обычная var и game var там дадут ошибку типа.

Операции присваивания ​

jc
event<player_join> {
  var x = 10
  x += 1; x -= 1; x *= 2; x /= 2; x %= 3
  x++
  x--
  var list = [1, 2, 3]
  list[0] += 5                    // op= работает и на элементах
  var copy = list                 // список копируется: copy[0] = 0 не изменит list
  copy[0] = 0
  player::message("x=$x, list=${list[0]}, copy=${copy[0]}")
}

Списки и словари — это значения, при присваивании они копируются. Подробнее — на странице Списки и словари.

Переменная с явной областью ​

В декомпилированном коде встречается var_raw("x", "game"). Это переменная с явно заданной областью (local, game, save, line), объявлять её не нужно. В новом коде пиши обычные объявления. См. Декомпилятор.

rpc для отладки ​

Перед game var и save var можно поставить слово rpc: rpc game var coins = 0. Тогда агент или ты сам сможете читать и менять эту переменную в работающем мире командами jmvcc client get и jmvcc client set. Работает только при деплое с --rpc, без него слово ни на что не влияет. Подробнее — на странице RPC агента.

Коротко ​

  • Монеты, рекорды, прогресс храни в save var %player%_x и задавай начальное значение через ??= в player_join.
  • Состояние игры (раунд, списки) — в game var.
  • Для данных события и его функций подходит var, черновики внутри функции — в line var.
  • Константы — в inline var.
  • Переменная, которой ничего не присвоили, равна 0. Список и словарь сначала создай.
