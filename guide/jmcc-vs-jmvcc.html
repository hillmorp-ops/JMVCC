jmcc и JMVCC ​

JMVCC — форк компилятора jmcc (rqbik и контрибьюторы, MIT). Язык JustCode, формат модулей и основные команды CLI остались те же (убрана только jmcc update: данные теперь встроены), и код для jmcc обычно компилируется как есть. Сверху добавлены оптимизатор, понятные ошибки, мост в игру, новые конструкции языка и свежие данные сервера.

Всё на этой странице можно проверить. Каждый пример jmcc собран настоящим jmcc 1.1.21 (последний коммит 2023-08), каждый пример JMVCC — нашим компилятором. Цифры взяты из журнала разработки и замеров на сервере, источник указан рядом.

Главное ​

Оптимизатор -O: меньше блоков, а действий не больше ​

В jmcc оптимизатора нет. В JMVCC флаг -O сжимает модуль по одному жёсткому правилу: на любом пути сервер выполняет столько же действий или меньше. Это проверяет тест с эталонным интерпретатором: на 2026-11-04 он гоняет корпус 4288 раз без -O и с -O, и ни один прогон не стал дороже. Выполненных действий 234453 → 229333, взвешенная цена 1136341 → 1114867 (OPT_REPORT=1 npx jest optimizer). Вживую тоже проверено, через deploy -O.

Единица цены — одно простое действие a = i (≈0.7 мкс). Словари дешевле в 4–6 раз даже без -O: сахар m[k] сразу компилируется в быстрые действия. Этих действий нет в данных jmcc вообще. Подробно — на странице Оптимизатор -O.

Мост в игру: одна команда вместо копирования ссылок ​

В jmcc путь такой: compile -u → скопировать ссылку → вставить /module loadUrl в чат → подтвердить книгу → искать ошибки в чате. В JMVCC мод JMVCC Bridge делает это одной командой:

text
jmvcc client deploy game.jc -O   # сборка → загрузка → /module loadUrl → подтверждение → /play → ошибки и log() в терминал

Ещё через мод можно:

  • читать ошибки сервера и log(...);
  • смотреть переменные;
  • делать скриншоты;
  • кликать в меню;
  • мягко останавливать код (graceful stop);
  • вызывать функции кода из терминала (RPC агента).

Язык: пишешь как думаешь ​

Есть операторы == != < > <= >= && || ! и return. Есть перечисления enum и структуры struct; они живут только в компиляторе, поэтому в JSON не попадает ничего лишнего. Ещё есть:

  • try / catch / throw и match;
  • словари m[k];
  • вложенные индексы grid[y][x];
  • типизированные параметры;
  • понятные имена действий: l.sort(), l.length(), player::give_item.

Код рядом ​

Здесь одна и та же задача решена дважды. На вкладке jmcc — код для jmcc: он собран настоящим jmcc и честно сделан так, как это можно сделать в jmcc. На вкладке JMVCC — то же на JMVCC. Под каждым примером указано, сколько действий выходит в JSON: в обработчике события, а где сказано, во всём модуле. Вложенные действия тоже считаются.

Фазы игры: enum + match ​

jmcc
// 0 = лобби, 1 = отсчёт, 2 = игра, 3 = конец
game var phase = 0

event<player_join> {
  if (phase.equals(0)) {
    player::message("&aЖдём игроков")
  } else if (phase.equals(1)) {
    player::message("&eСейчас начнём")
  } else if (phase.equals(2)) {
    player::message("&7Раунд идёт, ты зритель")
  } else {
    player::message("&cИгра окончена")
  }
}
jc
enum Phase { LOBBY, COUNTDOWN, GAME, END }
game var phase: Phase = Phase.LOBBY

event<player_join> {
  match (phase) {
    LOBBY -> player::message("&aЖдём игроков")
    COUNTDOWN -> player::message("&eСейчас начнём")
    GAME -> player::message("&7Раунд идёт, ты зритель")
    else -> player::message("&cИгра окончена")   // END
  }
}

Действий: jmcc 10, JMVCC 10. С -O три equals (≈8 каждое) становятся number_in_range (≈1.5), и путь до «Игра окончена» дешевеет с ≈24 до ≈4.5. Это заслуга -O, а не match: код с вкладки jmcc, собранный JMVCC с -O, ускоряется так же. Выигрыш enum в другом: вместо чисел — имена, и phase = 4 не написать по ошибке, компилятор ответит ошибкой типа.

Условия: && || ! ​

jmcc
game var %player%_hp = 20
game var %player%_class = 0

event<player_take_damage> {
  if (%player%_hp.less(5)) {
    if not (player::is_sneaking()) {
      var ok = 0
      if (%player%_class.equals(1)) {
        ok = 1
      }
      if (%player%_class.equals(2)) {
        ok = 1
      }
      if (%player%_class.equals(3)) {
        ok = 1
      }
      if (ok.equals(1)) {
        player::message("&cОсторожно!")
      }
    }
  }
}
jc
game var %player%_hp = 20
game var %player%_class = 0

event<player_take_damage> {
  if (%player%_hp < 5 && !player::is_sneaking() && (%player%_class == 1 || %player%_class == 2 || %player%_class == 3)) {
    player::message("&cОсторожно!")
  }
}

Действий: jmcc 11, JMVCC 13, JMVCC -O 4. Честно: без -O JMVCC здесь даже чуть больше, потому что || собирается через флаг. С -O получается if less { not sneaking { equals(class, [1, 2, 3], ANY) { … } } }. Так пишет руками опытный автор на jmcc, только здесь это вышло из обычного ||. Одно equals с тремя значениями стоит примерно как одно условие (cpu-bench).

Счётчик в словаре: m[k] ​

jmcc
game var no_keys = []
game var no_values = []
game var kills = variable::create_map(no_keys, no_values)

event<player_kill_player> {
  var n = kills.get_map_value("%killer%", 0)
  n += 1
  kills = kills.set_map_value("%killer%", n)
  player::message("Убийств: $n")
}
jc
game var kills = variable::create_map_from_values([], [])

event<player_kill_player> {
  var n = kills["%killer%"]
  kills["%killer%"] = n + 1
  player::message("Убийств: ${n + 1}")
}

Действий в событии: jmcc 4, JMVCC 3. Цена до сообщения: jmcc ≈6.3 + 1 + 10.7 ≈ 18, JMVCC ≈1.2 + ≈3.8 ≈ 5 (ops-bench: запись ≈1.8 и ещё ≈2 за %math в n + 1). Сообщение с ${n + 1} у JMVCC дороже простого $n примерно на 2, но в сумме словарь всё равно дешевле примерно в 3.5 раза. И ещё ловушка: если в jmcc написать kills.set_map_value("%killer%", 1) отдельной строкой, без kills = …, строка молча пропадёт.

Перехват ошибки: try / catch ​

В jmcc так нельзя. Блок controller_exception там без тела: code::controller_exception(e) без скобок собирается в пустой блок, а с телом выходит ошибка. Обернуть им ничего не получится:

text
var e
code::controller_exception(e) { … }
 Ошибка  Данное выражение не может быть использовано как лямбда-выражение
jc
event<player_join> {
  var rewards = [1, 2, 3]
  try {
    var part = rewards.slice(1, 9)    // за концом списка — ошибка сервера
    player::give_item(item("diamond"), part.length())
  } catch (e) {
    log("не вышло: $e")               // e = index_out_of_bounds
  }
  player::message("код дальше идёт")
}

JMVCC собирает это в 10 действий: блок сервера, флаг ошибки и тело catch. Код после try продолжает работать, а текст ошибки приходит в терминал через log.

  player::message("Монет: ${%player%.coins}, рекорд: ${%player%.best}")

Действий: 8 и 8. JMVCC выдаёт байт в байт тот же JSON, что и ручной код слева, собранный JMVCC. Выигрыш здесь не в скорости, а в длине кода: три проверки exists превратились в одну строку ??=. Поля структуры компилятор знает: на %player%.coinz он ответит «В struct Profile нет поля 'coinz' (%player%). Возможно: coins. Поля: coins, best, games».

Почему так ​

  • Почему не правка в jmcc. jmcc не обновлялся с 2023 года, его данные застыли на 721 действии. JMVCC поменял многое сразу: данные, язык, сообщения, оптимизатор, мост. Поэтому это отдельный форк.
  • Совместимость. Код для jmcc обычно собирается как есть. Исключения такие:
    • новые ключевые слова: return continue enum struct try catch finally throw match больше нельзя брать именами переменных;
    • аргументы лямбды только со стрелкой { i -> … }: старое { i с телом на следующей строке теперь ошибка;
    • код, который зависел от багов из таблицы выше: например, старый l[0] += 5 теперь действительно прибавляет;
    • длинные строки кода больше не режутся по 43 блока, поэтому их JSON другой (вернуть старое: --max-line 43).
  • Литерала словаря нет. Пустой словарь создаётся так: variable::create_map_from_values([], []). Литералы списков были и в jmcc, JMVCC только исправил вложенные и динамические элементы.
  • Цифры цены — это замеры на сервере (dev/research/ops-bench.md, сводка — в Оптимизаторе). Единица — одно a = i ≈ 0.7 мкс. 1% CPU мира ≈ 68–125 мкс кода за тик.
  • Без -O JSON почти не меняется: старый код даёт тот же модуль, кроме исправленных багов и снятой разбивки строк по 43 блока (вернуть: --max-line 43). -O — отдельный флаг, и его гарантию проверяют тесты с эталонным интерпретатором.
