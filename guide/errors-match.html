Ошибки и match ​

try / catch / throw и match — сахар компилятора. В модуль попадает обычный код JustMC: блок «Уловить ошибку» (code::controller_exception) с флагом и цепочка if / else, как написал бы руками. Всё ниже проверено на сервере (server-check-34, -35, -36).

try / catch ​

jc
function give_reward(n) {
  player::give_item(item("diamond"), n)
}

event<player_join> {
  var rewards = [1, 2, 3]
  try {
    var part = rewards.slice(1, 9)  // за концом списка — ошибка сервера: тело try обрывается здесь
    give_reward(part.length())      // ошибки в вызванных функциях тоже ловятся (и после code::wait)
  } catch (e) {
    log("не вышло: $e")             // e — текст: id ошибки (здесь index_out_of_bounds)
  }
  log("дальше")                     // код после try / catch идёт всегда
}
  • catch выполняется только если была ошибка. Без ошибки e не трогается.
  • В e всегда текст: у ошибки сервера — её id, у throw("...") — само сообщение.
  • catch { } без имени и try { } без catch (просто проглотить ошибку) тоже можно.
  • catch (lastError) с именем существующей переменной (например, game var lastError) пишет ошибку прямо в неё.
  • finally нет: код после блока и так выполняется. Типа у ошибки нет: catch (e: text) — ошибка с подсказкой.

throw ​

jc
function take(hp, damage) {
  if (damage < 0) {
    throw("урон меньше нуля: $damage")
  }
  return hp - damage
}

event<player_join> {
  try {
    var hp = take(20, -5)
  } catch (e) {
    player::message("&cОшибка: $e")   // «урон меньше нуля: -5»
  }
}

throw("сообщение") (или throw "сообщение") — это code::throw_error("throw", сообщение, "ERROR"): строка кода обрывается, ближайший try его ловит. id ошибки нигде не виден (ни в e, ни в логе), поэтому у throw одно значение. code::throw_error(..., "WARNING") и "FATAL" только пишут в лог: код идёт дальше, catch их не видит.

Выходы изнутри try ​

Работают как обычно:

  • return / return x в функции — выход из функции;
  • break / continue цикла вокруг try — выход из цикла / следующий шаг;
  • return / break в событии или процессе — конец потока. Блок сервера end_thread выходит только из блока ошибки, поэтому компилятор ставит флаг и после блока завершает поток сам.
jc
event<player_join> {
  repeat::multi_times(5) { i ->
    try {
      if (i == 2) {
        continue
      }
      if (i == 4) {
        break
      }
      player::message("шаг $i")
    } catch (e) {
      log("шаг $i: $e")
    }
  }
}

Вложенные try, try в цикле и в рекурсии работают верно: внутренний ловит своё, внешний — только ошибки снаружи внутреннего (и throw из внутреннего catch).

Одно исключение: code::end_thread() или break вне цикла внутри функции, вызванной из try, выходит только из тела try: запускается catch (e при этом прежняя), код после try идёт дальше. Компилятор предупреждает у вызова (try-end-thread). Верни из функции флаг и выйди в самом теле try:

jc
function allowed(msg) {
  if (value::health < 5) {
    player::message(msg)
    return 0
  }
  return 1
}

event<player_join> {
  try {
    if (allowed("мало здоровья") == 0) {
      return            // конец события: try сам завершит поток после блока
    }
    player::message("дальше")
  } catch (e) {
    log("ошибка: $e")
  }
}

Цена ​

try { } catch (e) { } стоит ≈3 простых действия поверх тела: флаг 1 → блок ошибки → флаг 0 → проверка флаг > 0. Это дешевле, чем проверять саму e: != ≈6, is_type ≈7, а > и number_in_range на тексте — ошибка сервера. try без catch и без выходов — ровно один блок «Уловить ошибку».

match ​

jc
enum Phase { LOBBY, GAME, END }
game var phase: Phase = Phase.LOBBY

event<player_join> {
  match (phase) {
    Phase.LOBBY -> player::message("&aЖдём игроков")
    GAME, END -> {
      player::message("&7Раунд уже идёт")
    }
  }

  match (value::health) {
    20 -> player::message("полное здоровье")
    1, 2, 3 -> player::message("&cпочти мёртв")
    else -> player::message("ранен")
  }
}
  • x считается один раз: не переменная (value::health, f(), l[i]) — во временную.
  • Ветка — значение (число, текст, член enum, переменная) или несколько через запятую: одно if_variable_equals со списком. Тело — один оператор или { блок }. Ветки — с новой строки, через ; или ,.
  • else -> ... — все остальные, только последней. Выполняется ровно одна ветка.
  • match — оператор, а не выражение: var label = match (x) { ... } — синтаксическая ошибка, значение в ветке (1 -> "one") — ошибка. Присваивай в каждой ветке:
jc
event<player_join> {
  var label = ""
  match (value::health) {
    20 -> label = "полное"
    else -> label = "ранен"
  }
  player::message(label)
}
  • В JSON — ровно if (x == a) { } else if (variable::equals(x, [b, c])) { } else { }. С -O ветка с одним числом становится number_in_range (≈1.5 вместо ≈8), если x — числовая переменная.
  • По enum: голое имя члена (GAME) — как Phase.GAME; член чужого enum — ошибка; без else компилятор предупредит, каких членов нет.
  • Ошибки с подсказкой: повтор значения, => (стрелка — ->, как в { i -> ... }), _ / default (пиши else), список [1, 2] (пиши 1, 2), условие x > 1 (для условий — if). switch / when / case нет — компилятор подскажет match.

try, catch, finally, throw, match — ключевые слова: переменную так не назвать. Внутри скобок это по-прежнему имена аргументов: variable::purge(["a"], match = "STARTS_WITH") работает.
