Списки и словари ​

Списки и словари в JustMC — обычные значения переменной. Важно помнить три вещи: индексы с 0, при присваивании всё копируется, а неприсвоенная переменная — это число 0, а не пустой список.

Списки ​

jc
event<player_join> {
  var l = [10, 20, 30]
  var first = l[0]              // 10: индексы с нуля
  l[1] = 25
  l[2] += 5                     // 35
  var n = l.length()            // 3
  player::message("$first, длина $n: $l")
}

Добавить и убрать:

jc
game var queue = []

event<player_join> {
  line var who = "%player%"
  queue.append(who)                    // в конец
  queue.append(["бот1", "бот2"])       // несколько разом: одно действие дешевле двух
  if (queue.index_of(who) > -1) {      // есть в списке?
    player::message("Ты в очереди")
  }
  queue.remove(who, remove_mode = "ALL")
}

Действие с изменением, написанное отдельной строкой (queue.append(...), l.sort()), меняет саму переменную. Действие-запрос надо куда-то положить: l.length() одной строкой — ошибка.

Сначала создайте список

append на переменной, которой ничего не присваивали, молча ничего не делает: ошибки нет, списка тоже нет. remove на такой — ошибка сервера. Создавайте заранее: var l = [] или l ??= [] для game/save var.

Понятные имена ​

У действий есть имена JMVCC — короче и привычнее серверных: l.append(x) вместо list_append_value, l.length() вместо get_list_length. JSON тот же; серверное имя тоже работает, без предупреждений. В справочнике и в jmvcc sig сверху наше имя, ниже — «на сервере: …».

Одно слово — одна идея: sort, length, contains, get, set, remove и другие сами выбирают действие списка, словаря или текста по тому, что лежит в переменной (как x[k]: что видно по коду выше).

jc
event<player_join> {
  var l = [3, 1, 2]
  l.sort()                                  // sort_any_list
  var m = variable::create_map_from_values(["a", "b"], [2, 1])
  m.sort(sort_type = "VALUES")              // sort_any_map
  var t = "привет"
  var n = l.length() + m.length() + t.length()   // три разных действия
  if (t.contains("ив")) { player::message("$n") }
  var pick = l.random()                     // случайный элемент
  var part = l.slice(0, 2)                  // [1, 2]: с 0, конец не включён
  m.set("c", 3)                             // то же, что m["c"] = 3
}

Проверено на сервере (server-check-29):

  • slice(a, b) — с 0, конец не включён, как в JS: [10, 20, 30, 40, 50].slice(1, 3) → [20, 30]. У списка выход за конец, a > b или отрицательный номер — ошибка сервера index_out_of_bounds; у текста номера обрезаются: "abcdef".slice(2, 9) → "cdef".
  • l.append(other) со списком добавляет его одним элементом: [1, 2] → [1, 2, [3, 4]]. Все элементы — l.extend(other).
  • m.merge(other) при одинаковых ключах берёт значение из other.
  • t.index_of("c") и t.get_char_at(i) — с 0, нет подстроки — -1.

У параметра функции вид берётся из типа (function f(m: map)) или из всех вызовов функции, у результата функции — из её return (подробно — Типы параметров). Если вид всё равно не видно (значение из события, функцию нигде не вызывают), компилятор берёт список и предупреждает (kind-guessed), называя точное имя для словаря или текста. Явный промах — ошибка с заменой: m.contains(k) → «ключ словаря — m.has_key(k)», l.clear() → «l = []», t.sort() — у текста нет сортировки, l.has_key(0) → «l.contains(v)», m.append(5) → «m[k] = v».

Вид виден и по результату действия в переменной: var s = parts.join("-") — текст, var t = value::display_name — текст, var n = l.length() — число. x.get("k") / x.set("k", v) с текстовым ключом — словарь, как x["k"]. Через :: получатель — первый аргумент и меняется на месте: variable::sort(m) — то же, что m.sort(). l.add(x) — это сумма чисел, компилятор подскажет l.append(x).

Обход ​

jc
event<player_join> {
  var scores = [5, 12, 7]
  var big = []
  repeat::for_each_in_list(scores) { i, v ->
    if (v > 6) { big.append(v) }   // меняем ДРУГОЙ список
  }
  player::message("Больше 6: $big")
}

Менять список, по которому идёт for_each_in_list, нельзя: цикл молча оборвётся после текущего шага. Компилятор предупреждает (loop-list-modified).

Словари ​

Литералов словаря нет. Пустой словарь создаётся действием, потом в него пишут по ключу:

jc
event<player_join> {
  var m = variable::create_map_from_values([], [])   // пустой: размер 0, текст {}
  m["gold"] = 5
  m["gold"] += 1
  var g = m["gold"]                                  // 6
  var keys = m.keys()
  player::message("золото: $g, ключи: $keys")
}

Для game var и save var создавайте через ??=: создаст словарь, только если его ещё нет, и не затрёт накопленное при следующем входе или старте мира.

jc
save var top_scores   // словарь: имя игрока → очки

function save_score(score) {
  top_scores ??= variable::create_map_from_values([], [])
  top_scores["%player%"] = score              // новый ключ добавится сам
}

event<player_join> {
  save_score(10)
}

Без create_map_from_values строка обрывается

set_map_value (и m[k] = v) на переменной, которой не присваивали, — ошибка сервера «Ожидал аргумент "Словарь для изменения" с типом Словарь, но получил Число». Остаток строки кода не выполнится.

Обход и топ ​

sort у словаря (sort_any_map) сохраняет порядок: и get_map_key_by_index, и for_each_in_map идут уже по отсортированному словарю.

jc
save var top_scores

function broadcast_top(n) {
  line var sorted = variable::sort(map = top_scores, sort_order = "DESCENDING", sort_type = "VALUES")
  line var size = sorted.length()
  if (size > n) { size = n }
  if (size == 0) { return }
  repeat::on_range(0, size - 1) { i ->          // on_range включает конец
    line var name = sorted.get_map_key_by_index(i)
    line var score = sorted[name]
    player::message<all_players>("${i + 1}. $name — $score")
  }
}

event<player_join> {
  top_scores ??= variable::create_map_from_values([], [])
  repeat::for_each_in_map(top_scores) { k, v ->
    player::message("$k: $v")
  }
  broadcast_top(5)
}

Топ в чат здесь только для примера. В настоящей игре выводите его на табло из текстовых дисплеев, см. Текст и интерфейс.

Как компилятор понимает x[k] ​

x[k] — это словарь, если выше по коду x создали или использовали как словарь (create_map*, sort_any_map, x["k"] = ..., x передан как map в действие variable::), или если ключ — текст ("k", "%player%", переменная с текстом, value::uuid), или если x — параметр с типом m: map. Иначе это список (ключ — число).

  • Ничего не известно ни про x, ни про k — будет список и предупреждение.
  • Текстовый индекс у известного списка — ошибка компиляции. Создайте словарь выше по коду (тогда работают и m.get(k) / m.set(k, v)).
  • Для game/save var «выше по коду» значит «выше в файле»: событие, которое создаёт словарь, ставьте над обработчиками, которые по нему индексируют.

Вложенные списки и словари ​

jc
event<player_join> {
  var grid = [[0, 0, 0], [0, 0, 0]]
  var y = 1
  var x = 2
  grid[y][x] = 1
  grid[0][1] += 5
  var c = grid[y][x]                    // 1
  grid[0].append(9)                     // тоже записывается обратно в grid

  var m = variable::create_map_from_values([], [])
  m["row"] = [1, 2]
  m["row"][0] += 1
  player::message("$c, $grid, $m")
}

Внутренний список читается во временную переменную, меняется и записывается обратно — компилятор делает это сам. Результат действия или функции — копия: m.keys()[0] = 5 — ошибка. Сначала положите в переменную: var keys = m.keys(); keys[0] = 5.

Копирование ​

var b = a для списка — копия. Изменение b не трогает a:

jc
event<player_join> {
  var a = ["x", "y"]
  var b = a
  b[0] = "z"
  player::message("a = $a, b = $b")     // a = [x, y], b = [z, y]
}

Отсюда цена: чтение списка из словаря или переменной копирует его, примерно 0.25 мкс на элемент. Не тяните большие списки каждый тик.

Нет элемента — что вернётся ​

Как читаетеИндекс за концом, -1, нет ключа
l[i], m[k] (сахар)0: компилятор сам передаёт default_value = 0, l[i] == 0 — истина
l.get(i), m.get(k) (get_list_value, get_map_value_single) без default_valuenull
те же с default_value = 77

null коварен: в тексте он печатается как 0, %math и < > читают его как 0, но == 0, == "0", == "" и number_in_range(0, 0) — ложь. В явных вызовах всегда передавайте default_value:

jc
event<player_join> {
  var m = variable::create_map_from_values([], [])
  var l = [1, 2]
  var a = m["нет"]                                            // 0
  var b = m.get("нет", default_value = 0)                    // 0
  var c = l.get(5, default_value = 0)                        // 0
  if (a == 0 && b == 0 && c == 0) { player::message("всё по нулям") }
}

Ещё по краям (проверено на сервере):

  • l[1.5] — как l[1].
  • l[i] и l.length() (get_list_length) не на списке (неприсвоенная, текст, словарь) — ошибка сервера, строка обрывается.
  • variable::list_value_equals(l, i, [v]) за концом или с -1 — ложь, без ошибки.
  • variable::is_empty(x) (list_is_empty) — истина для пустого списка, неприсвоенной переменной и пустого словаря.
  • Числа и тексты не равны: [1, 2, 3], элемент 1 с "2" не совпадёт.

В тексте ​

Списки и словари можно читать прямо в строке, без лишних действий:

ПлейсхолдерЧто даёт
%length(l)размер списка или словаря; длину текста; -1, если переменной нет
%index(l, 0)элемент с индексом (с 0); за концом — 0
%entry(m, ключ)значение по ключу; нет ключа — 0

Для локальных и строчных переменных — %length_local, %index_line и т. д. Интерполяция "$x" и "${l[0]}" сама компилируется в эти формы.

Цена операций ​

Замерено на сервере, в «присваиваниях» (a = i = 1):

ОперацияЦена
l[i] / l[i] = v≈1 / ≈1.5, от размера списка не зависит
m[k] / m[k] = v≈1.2 / ≈1.8
m.get_map_value(k) / m.set_map_value(k, v) (со списком ключей)≈6 / ≈11, только если ключей несколько
l.append(x)≈7.5: несколько значений — одним вызовом append([a, b])
l.index_of(x) (+ > -1)≈2.6, против ≈9 у l.contains(x)
m.has_key(k)≈9
сортировка 50 чисел≈67

Выбор по ключу (меню, тип клетки) делайте списком или словарём (LV[k], M[k]), а не цепочкой ==: десять веток if/else стоят ≈46 на каждый ключ. Больше — в Оптимизаторе.
