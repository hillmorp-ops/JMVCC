Команды CLI ​

Все команды jmvcc с опциями. Короткая справка есть и в самом CLI: jmvcc --help, jmvcc help compile, jmvcc client --help.

Запуск ​

ГдеКак звать
PowerShell / cmdjmvcc.cmd … из папки репозитория (или просто jmvcc, если она в PATH)
Git Bash / sh./jmvcc …
Без Nodejmvcc-win.exe … (как собрать — в Установке)
Напрямуюnode dist/index.js …

Старое имя jmcc — псевдоним, работает так же.

event<…> в терминале

< и > в шелле означают перенаправление. Имя события в sig пиши голым: jmvcc sig player_join. Форма 'event<player_join>' работает только в кавычках и не через jmvcc.cmd: тот передаёт аргументы в cmd.exe, и кавычки не спасают. Из Git Bash зови ./jmvcc.

Коды выхода ​

КодЧто значит
0всё хорошо
1ошибка: код не компилируется, деплой не удался, в логах error/critical, ничего не найдено
2decompile: круг нашёл различия, часть данных потеряется. client *: мост недоступен (игра без мода не запущена, bridge.json устарел, токен не подошёл)
3client *: игрок выключил управление /j remote off. Попроси его набрать /j remote on

Компилятор ​

compile ​

bash
jmvcc compile <путь> [опции]

Компилирует .jc в JSON-модуль. По умолчанию пишет <имя>.json рядом с исходником. При ошибке файл не пишется, код выхода 1.

ОпцияЧто делает
-o, --output <путь>куда записать JSON
-u, --uploadзагрузить модуль на m.justmc.ru и напечатать /module load-url force <ссылка>. Ссылка живёт 3 минуты
-O, --optimizeоптимизатор: меньше блоков, сервер выполняет столько же действий или меньше
-w, --warn-defaultsпредупреждать, где компилятор сам подставил значение перечисления или булева, и где аргумент остался пустым
-c, --compressJSON одной строкой, без отступов (с -u включается сам)
-s, --silentне писать файл, вывести результат в stdout
-d, --debugдля отладки самого компилятора. Ошибка в твоём коде печатается голым «Ошибка …» — без файла, строки и ^; стек виден только у внутренних ошибок компилятора. Для обычной работы не нужен
--max-line <n>резать строки длиннее n блоков на функции jmcc.fN. По умолчанию строки не режутся: лимита 43 блока у сервера нет. 43 — вывод прежних версий jmcc
--rpcdev-сборка с приёмником RPC агента. Без флага слово rpc в коде ничего не меняет
bash
jmvcc compile game.jc            # → game.json
jmvcc compile -O -u game.jc      # оптимизировать и загрузить
jmvcc compile game.jc -w         # показать подставленные умолчания

check ​

bash
jmvcc check <путь> [опции]

Проверяет файл без записи JSON и показывает все ошибки и предупреждения сразу, а не только первую. Код выхода 1, если есть хоть одна ошибка.

ОпцияЧто делает
-j, --jsonвывод в JSON (для агентов и скриптов)
-w, --warn-defaultsпредупреждать о подставленных умолчаниях
-O, --optimizeпроверять с оптимизатором
--max-line <n>как у compile
--rpcкак у compile

Обычный вывод — строка на каждую проблему и итог:

text
hello.jc:2:10 error [unknown-action] У 'player' нет действия или значения 'player::mesage'. Возможно: message. Сигнатура: player::message(messages: text[18], merging: SPACES|CONCATENATION|SEPARATE_LINES)
1 ошибок, 0 предупреждений

--json выдаёт то же самое объектом:

json
{
  "ok": false,
  "errors": 1,
  "warnings": 0,
  "diagnostics": [
    {
      "severity": "error",
      "kind": "semantic",
      "file": "hello.jc",
      "line": 2,
      "column": 10,
      "message": "У 'player' нет действия или значения 'player::mesage'. Возможно: message. …",
      "code": "unknown-action"
    }
  ]
}

Подсказки — буквально

В «Возможно: …» стоит готовая правка, а дальше — ожидаемая сигнатура. Обычно хватает подставить то, что предложено. Предупреждения («Предупреждение») значат, что код собрался, но ты использовал псевдоним или что-то подозрительное.

trace ​

bash
jmvcc trace <путь> [-O] [--max-line <n>] [--rpc]

Компилирует и печатает компактный листинг: события, функции и блоки в каждой строке. JSON не пишет. Нужен, чтобы сверить результат с замыслом и сравнить блоки с -O и без.

text
event<player_join> 3 блоков:
  player_send_title(title="&6Привет, %player%!", subtitle="&7Первый мир на JMVCC", fade_in=10, stay=60, fade_out=20)
  player_play_sound(sound=sound(entity.player.levelup, 1, 1))
  player_give_items(items=[item(diamond)], amount=1)

Справочник в терминале ​

sig ​

bash
jmvcc sig <имя> [-f]

Сигнатура и описание одного имени. Понимает действие (player::title, id player_send_title и псевдонимы), игровое значение (value::health), событие (player_join), фабрику (item) и плейсхолдер (%victim%). Для события показывает, кто в нём участвует, какие селекторы и value:: доступны.

ОпцияЧто делает
-f, --fullперечисления целиком, без сокращения …(N)
text
$ jmvcc sig player::title
player::title(title: text, subtitle: text, fade_in: number(ticks), stay: number(ticks), fade_out: number(ticks))
  id: player_send_title
  селекторы: player::title<current|default_player|killer_player|…|all_players>(...)
  Send Title / Отправить титул — Shows two captions to the screen for the selected player - a title and a subtitle.

Если имя не найдено, sig покажет до 10 похожих и вернёт код 1.

search ​

bash
jmvcc search <слова...> [-n <n>]

Ищет действия, игровые значения, события, а ещё id предметов и блоков по словам из имени или по смыслу: jmvcc search gold pressure plate.

ОпцияЧто делает
-n, --limit <n>сколько результатов, по умолчанию 20
text
$ jmvcc search give potion -n 3
player::give_potion_effect(potions: potion[18], overwrite: boolean=TRUE, show_icon: boolean=TRUE, particle_mode: REGULAR|AMBIENT|NONE)
entity::give_potion_effect(potions: potion[14], overwrite: boolean=TRUE, show_icon: boolean=TRUE, particle_mode: REGULAR|AMBIENT|NONE)
value::potion_effects: potion[]  [игровое значение]

reference ​

bash
jmvcc reference [-o <путь>]

Все сигнатуры, игровые значения и события одним текстом, удобно положить в контекст LLM. Из него собраны signatures.txt и Справочник этого сайта.

ОпцияЧто делает
-o, --output <путь>записать в файл вместо stdout

decompile ​

bash
jmvcc decompile <путь | ссылка> [опции]

Превращает JSON-модуль обратно в .jc: выгрузку из игры, результат compile или ссылку http(s):// на модуль. Затем сразу проверяет круг: компилирует результат и сравнивает с исходным JSON. Подробно — на странице Декомпилятор.

ОпцияЧто делает
-o, --output <путь>куда записать .jc. По умолчанию <имя>.jc рядом с JSON. Если такой файл уже есть и написан не decompile, будет <имя>.decompiled.jc
-f, --forceперезаписать существующий .jc, даже написанный руками
--allow-diffкод выхода 0, даже если круг нашёл различия
--no-verifyне проверять круг

Предметы с NBT уходят отдельным файлом <имя>.items.jc (константы item_raw), основной файл его импортирует.

Коды выхода: 0 — без потерь, 2 — есть различия (их список напечатан, эти данные потеряются при заливке), 1 — ошибка.

client: игра через мод ​

Команды jmvcc client … работают через мод JMVCC Bridge. Игра с модом должна быть запущена, CLI сам читает порт и токен из ~/.jmvcc/bridge.json. Мутирующие команды показывают игроку title «🤖 Агент работает» и не идут, если он выключил управление (/j remote off → код 3). Чтение (status, logs, vars, screen, items, shot) идёт без title и не блокирует ввод игрока. Только vars всё равно требует включённого управления: она шлёт серверу /env var list.

client status ​

bash
jmvcc client status

Адрес моста и версия мода, игрок и сервер, включено ли управление, текущая сессия логов, открытое окно, занят ли мост. С неё стоит начинать.

client deploy ​

bash
jmvcc client deploy <файл.jc | модуль.json> [опции]

Полная цепочка: компиляция (как compile -u) → загрузка → /build → /dev → /module load-url force … (книжку подтверждения мод примет сам) → /play → пауза → события новой сессии: ошибки, предупреждения, log(...), сообщения модуля. Готовый .json модуля заливается как есть.

ОпцияЧто делает
-O, --optimizeкомпилировать с оптимизатором
--no-playне запускать мир после загрузки
--wait <сек>сколько ждать событий после запуска, по умолчанию 5
--gracefulмягкая остановка перед /build: код доигрывает сессии и выполняет event<jmvcc_stop>. Если в коде её нет — обычный /build
--drain-timeout <сек>сколько коду доигрывать, 1..600, по умолчанию 90. Только с --graceful
--max-line <n>как у compile
--rpcзалить dev-сборку с приёмником RPC
text
✔ компиляция: game.jc
✔ загрузка: https://m.justmc.ru/api/…
деплой: build ✔ 1.6 с · dev ✔ 2.3 с · module ✔ 1.1 с · play ✔ 4.1 с
сессия 2026-11-02_19-01-50:
#12 19:01:53 log      вошёл Steve
итог: ok, событий 1

Код выхода 1, если шаг не прошёл или в логах есть error/critical. С --graceful первым шагом идёт drain, например drain ✔ 12.3 с (доиграно, таймаут кода 90 с). Если игрок отменил остановку, будет drain ✘ … cancelled, код 1, а /build не отправится.

client logs ​

bash
jmvcc client logs [опции]

События сессии из чата: ошибки кода, log(...), сообщения модуля и сервера. По умолчанию — текущая сессия без чата игроков. Внизу печатается последний seq, чтобы потом читать только новое.

ОпцияЧто делает
--errorsтолько error, critical, warning, code_notice
--types <a,b>типы через запятую: error, warning, critical, code_notice, log, system, broadcast, chat, session. Складывается с --errors
--since <seq>только события с seq больше этого
--session <id>другая сессия (id — из --all), по умолчанию текущая
--allвсе сессии
--jsonвывод в JSON

Строка ошибки: #17 19:01:52 error <действие>: <причина> @ x y z. Действие и причину пишет сервер, x y z — блок кода в мире разработки.

client stop ​

bash
jmvcc client stop [--timeout <сек>]

Только остановить мир, без заливки: мягкая остановка, потом /build. Если в коде нет мягкой остановки — /build сразу. --timeout 1..600, по умолчанию 90. Код 1 — остановку отменили или /build не прошёл.

client send ​

bash
jmvcc client send "<текст или /команда>"

Команда серверу (/play, /build) или сообщение в чат. Сообщения с ! (глобальный чат) мост не отправляет.

Git Bash и /команды

Git Bash превращает /build в путь Windows. CLI обычно это исправляет сам, но надёжнее писать "//build" или задать MSYS_NO_PATHCONV=1.

client vars ​

bash
jmvcc client vars <game|save> [подстрока] [опции]

Переменные мира со значениями прямо сейчас: обходит все страницы /env var list и печатает имя = значение. Видны только game и save, line и локальные — нет.

ОпцияЧто делает
--page <n>только эта страница (по 9 переменных)
--rawзначения как пишет сервер: {type: number, '7.0&Double'} вместо 7
--jsonвывод в JSON

Сбросить одну переменную: jmvcc client send "/env var clear game <точное_имя>".

/env var clear save без имени

Без имени команда стирает все сохранённые данные мира. Не делай так, если не уверен.

client items ​

bash
jmvcc client items [--all] [--json]

Предметы рюкзака (слоты 9–35) и открытого меню строкой сервера, сразу готовыми строками для .jc:

text
inline var ITEM_BILLIARD_CUE_BALL = item_raw("H4sI…")  // player_head "Billiard Cue Ball"

Так в код попадают головы /hdb и предметы с NBT: набери их в инвентарь и скопируй строки.

ОпцияЧто делает
--allещё хотбар, броня и вторая рука
--jsonraw, слоты, lore в JSON

Меню, клавиши, скриншоты ​

Для проверки игры глазами агента.

КомандаЧто делает
jmvcc client screenоткрытое окно (меню), его непустые слоты и кнопки
jmvcc client click <slot> [--right] [--shift]клик по слоту открытого окна (номер — из screen)
jmvcc client use [--off]правый клик предметом в руке (--off — во второй руке)
jmvcc client closeзакрыть открытое окно
jmvcc client button <текст...>нажать кнопку экрана по тексту: jmvcc client button Возродиться
jmvcc client key <клавиши...> [--ms <мс>]держать клавиши, по умолчанию 100 мс (50..10000): forward back left right jump sneak sprint swap_offhand drop attack use inventory hotbar1…hotbar9
jmvcc client shotскриншот игры, печатает путь к png
bash
jmvcc client key forward sprint --ms 2000

client control ​

bash
jmvcc client control begin
# … клавиши, клики, команды …
jmvcc client control end

Серия действий под одним предупреждением игроку, а не title перед каждым. Сессия сама кончается через 60 секунд без запросов. Для чтения (logs, vars, status) она не нужна.

client customclick ​

bash
jmvcc client customclick <namespace:path> [--snbt <snbt> | --text <текст>]

Шлёт серверу пакет custom click: код мира получит event<player_custom_click> без чата и окон. Ключ — в value::event_custom_click_key.

ОпцияЧто делает
--snbt <snbt>данные словарём SNBT: {cmd:"call",args:"[1]"}
--text <текст>данные одной строкой (в код приходят пустым словарём, для данных бери --snbt)

RPC: call, get, set, rpc-list ​

В разработке

RPC агента ещё обкатывается, подробности — на странице RPC агента.

Работают с кодом, залитым через client deploy … --rpc: зовут rpc function и читают или пишут rpc game var / rpc save var в работающем мире, без передеплоя.

КомандаЧто делает
jmvcc client call <fn> [args...]позвать rpc function и напечатать результат JSON. Аргумент — JSON (1, "a", [1,2]), если разбирается, иначе текст. Отрицательные числа — после --
jmvcc client get <var>значение rpc переменной (JSON)
jmvcc client set <var> <value>записать значение (JSON или текст) и напечатать новое
jmvcc client rpc-list [--json]какие rpc function (с параметрами) и rpc var есть в коде

У call и set есть ещё две опции:

ОпцияЧто делает
--textвсе аргументы (у set — значение) — текст как есть, без разбора JSON
--file <путь>аргументы — JSON-список из файла (у set — значение JSON из файла). Нужен в PowerShell: он портит кавычки в командной строке

У всех --timeout <сек>, по умолчанию 5. Код 1 — ошибка или нет ответа за таймаут.

Переменные окружения ​

ПеременнаяЧто делает
JMVCC_MAX_LINEто же, что --max-line, для всех команд (и для проверочной компиляции в decompile)
JMVCC_UPLOAD_DOMAINподменить хостинг модулей https://m.justmc.ru (для тестов). Старое имя JMCC_UPLOAD_DOMAIN тоже работает
FORCE_COLOR=0вывод без цветов, удобно для логов и агентов

Рабочий цикл ​

bash
jmvcc search <слова>          # найти действие, событие, значение
jmvcc sig <имя>               # точная сигнатура
jmvcc check main.jc           # все ошибки сразу
jmvcc trace main.jc           # сверить, во что скомпилировалось
jmvcc client deploy main.jc   # залить и запустить, прочитать ошибки сервера
jmvcc client logs --since N   # новые события после игры

Так же работают и ИИ-агенты.
