JMVCC для ИИ-агентов ​

JMVCC сделан так, чтобы агент (Claude Code и подобные) писал рабочую игру для JustMC с первого раза и сам чинил её. Для этого агенту нужны три вещи:

  1. Знание языка. Это llms.txt: синтаксис, ловушки сервера, рецепты и проверенные факты, одним файлом на английском. Подробнее — на странице llms.txt.
  2. Компилятор под рукой. jmvcc search и jmvcc sig вместо угадывания имён, jmvcc check со всеми ошибками сразу.
  3. Руки в игре. Мод JMVCC Bridge: агент сам заливает код, запускает мир и читает ошибки сервера.

Claude Code: скилл justmc ​

В репозитории лежит готовый скилл: dev/skill/SKILL.md. В нём рабочий цикл, ловушки, цена кода и правила «делай красиво». Claude Code сам включает его, когда просят игру, магазин, паркур или что угодно «для JustMC».

Установка — скопировать файл в папку скиллов:

bash
mkdir -p ~/.claude/skills/justmc
cp dev/skill/SKILL.md ~/.claude/skills/justmc/SKILL.md
powershell
New-Item -ItemType Directory -Force "$HOME\.claude\skills\justmc"
Copy-Item dev\skill\SKILL.md "$HOME\.claude\skills\justmc\SKILL.md"

Пути в скилле

Скилл и llms.txt ссылаются на D:\jmcc (там компилятор у автора). Если репозиторий лежит в другом месте, поправь пути в своей копии SKILL.md.

Другой агент ​

Скиллов нет — не беда. Дай агенту в контекст llms.txt (ссылкой или файлом) и коротко скажи, как работать:

text
Ты пишешь код для сервера JustMC на JustCode (.jc), компилятор — jmvcc.
Прежде чем писать, прочитай llms.txt целиком. Имена действий не угадывай:
jmvcc search <слова>, jmvcc sig <имя>. После каждой правки — jmvcc check main.jc,
исправляй по «Возможно: …» буквально. В игру — jmvcc client deploy main.jc,
читай вывод и чини, пока ошибок нет.

Весь API (каждое действие, значение и событие одной строкой) — в signatures.txt. Он большой (около 30 тысяч токенов), поэтому целиком в контекст его лучше не класть: пусть агент ищет по нему или зовёт jmvcc search.

Рабочий цикл ​

bash
jmvcc search gold pressure plate   # найти действие, значение, событие или id предмета по смыслу
jmvcc sig player::title            # сигнатура и описание
jmvcc sig player_kill_player       # событие: участники, плейсхолдеры, что заполнено в value::
jmvcc check main.jc --json         # все ошибки и предупреждения сразу
jmvcc trace main.jc                # во что скомпилировалось — сверить с замыслом
jmvcc client status                # игра с модом запущена, игрок на сервере, управление включено
jmvcc client deploy main.jc        # залить, запустить, напечатать ошибки сервера и log(...)
jmvcc client logs --errors         # ошибки текущей сессии
  1. Агент пишет main.jc в папке игры пользователя.
  2. jmvcc check — и правит всё, что нашлось. В ошибках есть «Возможно: …» и ожидаемая сигнатура: их нужно применять буквально.
  3. jmvcc client deploy — читает вывод. Строка ошибки выглядит так: #17 19:01:52 error <действие>: <причина> @ x y z, где x y z — блок кода.
  4. Чинит и повторяет, пока ошибок нет. Потом jmvcc client shot — посмотреть на результат глазами игрока.

Для отладки — log(...): строки попадают в jmvcc client logs. А jmvcc client vars game показывает значения переменных прямо сейчас.

jc
save var %player%_best

event<player_join> {
  %player%_best ??= 0
  log("рекорд %player% =", %player%_best)
  player::action_bar("&#5394f5&lРекорд: &f${%player%_best}")
}

Коды выхода jmvcc client: 1 — ошибка или деплой не удался, 2 — мост недоступен (попроси запустить игру с модом), 3 — игрок выключил управление (/j remote off): напиши ему об этом и попроси /j remote on.

Серия действий

Если агент жмёт клавиши, кликает меню и шлёт команды подряд, их стоит обернуть в jmvcc client control begin … jmvcc client control end. Тогда игрок увидит одно «Агент работает» вместо десятка. Чтению (логи, vars, status) это не нужно.

Правила из скилла ​

Коротко, что агент должен держать в голове. Подробно и с проверками — в llms.txt и разделе Грабли и факты сервера.

Ловушки, которые ломают код молча

  • var в функции общая с вызывающим, параметры тоже. Черновые значения в функциях — line var.
  • Ошибка сервера обрывает остаток строки кода, в том числе у того, кто вызвал функцию. Рискованное выносят в process — он, по выводу (не проверено), своя строка кода.
  • Неприсвоенная переменная — это число 0. Перед словарём или списком: m ??= variable::create_map_from_values([], []), l ??= [].
  • Поток умирает вместе со своей целью: игрок вышел — его цикл встал. Мировой цикл ставят в верхний код или в процесс без цели (NO_TARGET).
  • Две функции с одним именем выполняются обе.
  • /build и деплой рвут все потоки сразу. Игры с долгими сессиями заворачивают вход в std::session(...), а возврат ресурсов пишут в event<jmvcc_stop> — см. Мягкая остановка.

Цена кода

  • == стоит около 8 действий, > и < — около 1. В горячих циклах числа сравнивают без ==.
  • m[k] и m[k] = v дешёвые, get_map_value / set_map_value со списком ключей в 4–6 раз дороже.
  • Эффекты — только по событию, HUD — раз в секунду одним мировым циклом. Подробнее — Оптимизатор -O.

Делай красиво

Игру оценивают глазами, от первого лица. «Работает» — мало.

  • Информация — прямо на объекте (текстовые дисплеи на блоках), а не легендой сбоку.
  • Чат — худший канал. Уведомления идут в action bar со звуком, большие события — в title, топы — на табло из дисплеев.
  • Управление — через механики игры (event<player_input_event> для WASD), а не «4 предмета в хотбаре».
  • Перед «готово» — деплой, jmvcc client shot и проверка скриншота.

Приёмы и точные числа — в разделе Текст и интерфейс и в llms.txt («Look and feel»).

Нельзя

  • Слать сообщения с !: это глобальный чат, мост их не отправляет.
  • Обходить remote_disabled. Игрок выключил управление — значит, надо сказать ему об этом.
  • Деплоить в чужой или рабочий мир, не предупредив: деплой стирает код мира.
  • Выдумывать головы и особые предметы. Агент просит пользователя набрать их в инвентарь, потом зовёт jmvcc client items.
  • /env var clear save без имени стирает все сохранённые данные мира. Только если пользователь сам попросил.
